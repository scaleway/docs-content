## Problem

When my Serverless Container instance starts, I get errors such as:

- "No route to host" error message
- "Connection timeout" error message
- Other connection failures when trying to reach other resources in the same Private Network (such as databases, Instances, etc.)

<Message type="note">
  This known issue is limited to the `fr-par` region and for containers attached to a Private Network.
</Message>

## Cause

The Serverless Container instance starts on a node where the Private Network is not yet fully available.

The container instance waits for the metadata service (169.254.169.254) to be reachable before starting, but this does not guarantee that all resources in the Private Network are reachable.

## Solutions

The connection issue automatically resolves itself within less than 3 minutes. However, you can follow these solutions to ensure reliable connectivity at startup.

### Solution 1: Implement connection retry logic (recommended)

1. **Configure connection retries**: If your container tries to connect to a resource in the Private Network at startup, implement retry logic with configurable timeouts.

2. **Configure startup probes**: Set up the container startup probe to return a `200` status code only when all required Private Network resources are reachable. This prevents traffic from being routed to a container instance before it is fully ready.

3. **Set appropriate timeouts**: Configure connection timeouts to allow sufficient time for the network to become available (up to 3 minutes).

### Solution 2: Use a different region

This issue only occurs in the `fr-par` region due to the high density of resources. You can deploy your containers in a different region to avoid this issue.

### Solution 3: Use dedicated Private Networks

The issue does not occur when both the container and the resource it needs to reach are in different Private Networks (but within the same VPC). 

1. In a VPC, create a Private Network dedicated to your containers.
2. Place your containers in this dedicated Private Network.
3. In the same VPC, create another Private Network for the resources your containers need to reach (databases, Instances, etc.).
4. Place the resources in this separate Private Network.
