Object Storage lets you store and retrieve any kind of data, such as documents, images, videos, or backups, over HTTP(S) with the Amazon S3 API. You do not provision capacity or attach anything to a server: any authorized application can reach your data from anywhere. Object Storage suits large volumes of data that applications read and write as whole files. It does not suit workloads that need a disk or a shared file system.

## How Object Storage works

Object Storage organizes data around the following elements:

- **Bucket**: a container for objects. Settings such as versioning, encryption, and bucket policies apply at the bucket level.
- **Object**: a file and its metadata. Each object has its own storage class and visibility.
- **Key**: the unique name of an object in a bucket, such as `photos/2026/beach.jpg`.
- **Metadata**: information stored with the object, such as its content type, tags, and custom `x-amz-meta-*` values.

Buckets have a flat structure. Folders do not exist as such: the `photos/2026/` part of a key is a [prefix](/object-storage/concepts/glossary/#prefix), which tools use to group and display objects as if they were in folders.

Applications access objects through HTTP(S) requests such as `PUT`, `GET`, and `DELETE`. To change an object, you upload a new version of the whole object, which replaces the previous one.

Object Storage provides read-after-write consistency for `PUT` and `DELETE` requests, on new and existing objects. Any `GET` or `LIST` request sent after a successful write immediately reflects the change. For example, a new object appears in the object list of the bucket as soon as its upload succeeds, and a deleted object can no longer be read.

See the [Object Storage glossary](/object-storage/concepts/glossary/) for the definition of each term.

## Main features

### Storage classes

Each object has a storage class that matches how often you access it, from immediate access to long-term archiving. You select the class at upload, and can change it later. See [Understanding storage classes](/object-storage/storage-classes/understanding-storage-classes/).

### Lifecycle rules

Lifecycle rules automate the management of your objects over time. They transition objects to colder storage classes, expire objects and their versions, and abort incomplete multipart uploads. See [How to manage lifecycle rules](/object-storage/storage-classes/lifecycle-rules/).

### Multipart uploads

Multipart uploads split a large object into independent parts that you can upload in parallel and retry individually. Object Storage then assembles the parts into a single object. See [Manage multipart uploads](/object-storage/objects/multipart-uploads/).

### IAM and bucket policies

IAM policies control which Object Storage actions users, groups, and applications can perform at the Project level. Bucket policies refine this access for a specific bucket or prefix. See [Understanding access control](/object-storage/access-control/understanding-access-control/).

### Visibility and temporary links

All objects are private by default. You can make an object public, or share a private object for a limited time with a temporary link. See [How to manage object visibility and sharing](/object-storage/access-control/object-visibility-and-sharing/).

### Versioning

Versioning keeps several versions of each object in a bucket, so that you can recover from accidental overwrites and deletions. See [How to use bucket versioning](/object-storage/data-protection/versioning/).

### Object lock

Object lock prevents objects from being deleted or overwritten for a defined retention period. It requires versioning. See [How to use object lock](/object-storage/data-protection/object-lock/).

### Encryption

Object Storage encrypts data in transit with TLS. At rest, you can encrypt objects with keys managed by Scaleway, by your Organization in Key Manager, or by you. See [Understanding encryption](/object-storage/data-protection/understanding-encryption/).

### Bucket website

The bucket website feature lets you host a static website directly on a bucket. See [How to host a static website on a bucket](/object-storage/buckets/bucket-website/).

### Metrics and logs

Object Storage sends metrics and logs to Cockpit, so that you can monitor your objects, storage usage, bandwidth, and requests. See [How to monitor Object Storage usage](/object-storage/optimization-monitoring/monitor-usage/).

## Ways to use Object Storage

### Scaleway console

The Scaleway console lets you manage buckets and objects from your web browser. It suits discovering the product and occasional operations. See the [Object Storage - Quickstart](/object-storage/quickstart/).

### Amazon S3-compatible CLI tools

Command-line tools such as the AWS CLI, rclone, MinIO Client, and s3cmd suit scripts, bulk operations, and large data sets. See [Configure CLI tools and clients for Object Storage](/object-storage/api-clients/cli-tools-and-clients/).

### Scaleway CLI

The Scaleway CLI generates configuration files for rclone, s3cmd, and MinIO Client from your existing Scaleway credentials. See [Scaleway CLI for Object Storage](/object-storage/api-clients/scaleway-cli/).

### Amazon S3 API and SDKs

The Amazon S3 API and SDKs let you integrate Object Storage into your applications. Applications and tools that support the Amazon S3 protocol work with Object Storage once you configure your Scaleway API key and endpoint. See [Supported Object Storage API calls](/object-storage/api-clients/s3-api-support/).

### Typical setup

A typical setup follows these steps:

1. [Create a bucket](/object-storage/buckets/create-a-bucket/).
2. [Configure access](/object-storage/access-control/understanding-access-control/) with IAM and, if needed, a bucket policy.
3. [Upload your objects](/object-storage/objects/upload-objects/) and select their storage class.
4. [Create lifecycle rules](/object-storage/storage-classes/lifecycle-rules/) to manage your objects over time.
5. [Monitor your usage](/object-storage/optimization-monitoring/monitor-usage/) with Cockpit.

## Compare Object Storage with other storage solutions

Scaleway offers several storage products, which answer different needs:

| Criteria | Object Storage | [Block Storage](/block-storage/quickstart/) | [File Storage](/file-storage/quickstart/) | [Local Storage](/local-storage/quickstart/) |
|---|---|---|---|---|
| Data model | Objects in buckets, with a flat structure | Network-attached volumes that behave like regular disks | Files and folders in a hierarchy | All-SSD volume hosted on the hypervisor of the Instance |
| Access | HTTP(S) requests with the Amazon S3 API | Attached to an Instance | Attached to Instances or Kubernetes Kapsule | From the Instance only |
| Sharing | Any authorized client, from anywhere | Through the Instance it is attached to | Several Instances work on the same files | None |
| Capacity | No capacity to provision | Provisioned, up to 15 TB per volume | Provisioned, from 25 GB to 50 TB per file system | Fixed by the Instance type |
| Data changes | Whole objects replaced | In place | In place | In place |
| Performance focus | Throughput on large and concurrent transfers | Disk operations for Instances | Scales with the provisioned capacity | Low latency on local NVMe |
| Typical uses | Backups, archives, media, static websites, data sets | Boot volumes, databases, Instance storage | Shared application files, Kubernetes workloads | Temporary data and fast scratch space |

### Advantages

- **Capacity**: you store data without provisioning, resizing, or attaching volumes.
- **Accessibility**: applications reach your data over HTTP(S), from anywhere, without a server in front of it.
- **Compatibility**: the Amazon S3 API gives you access to a wide range of existing tools and SDKs.
- **Automation**: storage classes and lifecycle rules manage your data as it ages, without manual operations.
- **Built-in data protection**: versioning, object lock, and encryption are configurable on each bucket.

### Limitations

Object Storage is not a disk or a file system, which has the following consequences:

- **No partial updates**: you cannot edit part of an object or append to it. You must replace the whole object.
- **No native mount**: Instances cannot use a bucket as a disk or a POSIX file system. Tools such as [s3fs](/tutorials/object-storage-s3fs/) can expose a bucket as a file system, but do not make it behave like one.
- **No low-latency disk workloads**: Object Storage does not suit databases, operating systems, or other workloads that need fast random access.
- **Restore delay for archives**: you must [restore objects in the Glacier class](/object-storage/storage-classes/restore-from-glacier/) before you can read them.

The following limits also apply:

| Element | Limit |
|---|---|
| Object size | 5 TB |
| Size of a single `PUT` request | 5 GB. Use [multipart uploads](/object-storage/objects/multipart-uploads/) above this size. |
| Parts per multipart upload | 1,000 |
| Versions per object | 1,000 |
| Lifecycle rules per bucket | 1,000 |
| Bucket policies per bucket | 1 |
| Objects per batch deletion in the console | 1,000 |

Bucket names must be unique across the whole platform, and follow specific [naming rules](/object-storage/faq/#is-there-a-limitation-on-the-bucket-name). Object Storage also applies a [rate limit on PUT operations](/object-storage/troubleshooting/performance-and-rate-limits/#i-get-request-rate-errors).

The console has technical limits when it browses large buckets. Scaleway recommends using [dedicated tools](/object-storage/api-clients/cli-tools-and-clients/) to manage large data sets.

### Choose the right storage solution

| You need to | Use |
|---|---|
| Store large volumes of unstructured data, and access it from anywhere | Object Storage |
| Archive data that you rarely access | Object Storage, with the Glacier storage class |
| Boot an Instance or run a database | Block Storage |
| Share files and folders between several Instances | File Storage |
| Keep fast, temporary data on an Instance | Local Storage |

## Common use cases

- **Static website hosting**: use the bucket website feature, public objects, and Edge Services. See [How to host a static website on a bucket](/object-storage/buckets/bucket-website/).
- **Backups**: use versioning, object lock, and lifecycle rules. See [Creating backups with Restic and Object Storage](/tutorials/restic-s3-backup/).
- **Long-term archiving**: use the Glacier storage class, lifecycle rules, and object lock. See [Understanding storage classes](/object-storage/storage-classes/understanding-storage-classes/).
- **Media and content delivery**: use multipart uploads, temporary links, and Edge Services. See the [Edge Services - Quickstart](/edge-services/quickstart/).
- **Sensitive and regulated data**: use encryption, bucket policies, and object lock. See [How to create a compliant bucket to host healthcare data](/object-storage/data-protection/host-healthcare-data/).
