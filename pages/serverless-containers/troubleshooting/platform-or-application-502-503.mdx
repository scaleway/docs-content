## Problem

My Serverless Container returns `502` or `503` errors during high traffic or scale-ups. I cannot determine whether these errors come from my application code, or whether the requests were refused by the platform and never delivered to my application.

## Cause

The platform generates `502` errors when a new container instance fails its startup verification during a scale-up, and `503` errors when the request queue is full after the maximum scale (`maxScale`) of the container is reached.

The platform does not currently add any specific status, header, or structured reason to the responses it generates. From a client perspective, a platform-generated `502` or `503` error is identical to an application-generated one.

## Possible solutions

No native marker is available to differentiate platform-generated errors from application-generated errors. Set a custom response header in your application to identify the responses it produces.

1. In your application code, set a custom response header, such as `X-Served-By: my-application`, on every response using an HTTP middleware.
2. When you receive a `502` or `503` error, check whether this header is present in the response.

If the header is present, your application generated the error, meaning the request reached your application code. If the header is absent, the platform generated the error, meaning the request was never delivered to your application code.
