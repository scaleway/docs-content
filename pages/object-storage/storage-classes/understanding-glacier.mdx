Glacier is the cold storage class of Object Storage, designed for deep archiving. Cold data is data you access rarely and do not need immediately, as opposed to hot data, which you access frequently. Objects in the Glacier class remain listed in your bucket, but you must restore them before you can download them.

## When to use Glacier

Use Glacier for data that does not require immediate access, such as legal documents or long-term backups. Scaleway recommends Glacier for data that you may need only once or twice in a decade.

For frequently accessed data, such as static assets, streaming, Content Delivery Network (CDN) content, or work documents, use the Standard Multi-AZ class. See [Understanding storage classes](/object-storage/storage-classes/understanding-storage-classes/) to compare the available classes.

<Message type="tip">
Store average-sized files (larger than 1 MB) in Glacier, rather than many small files. This makes restoration easier and helps you retrieve your data faster.
</Message>

## Glacier location and availability

The Glacier storage cluster is located in DC4, an underground data center 25 meters below Paris, which provides an additional layer of security. The cluster is accessible from any bucket in the Paris (fr-par) and Amsterdam (nl-ams) regions. You cannot transfer objects to Glacier from the Warsaw (pl-waw) region.

## Move objects to Glacier

You can move objects to Glacier in the following ways:

- **At upload**: select the Glacier class in the console, or specify it with the API. See [How to upload objects](/object-storage/objects/upload-objects/).
- **For a single object**: edit the storage class of an existing object. See [How to edit the storage class](/object-storage/storage-classes/manage-storage-classes/).
- **For many objects or a whole bucket**: create a [lifecycle rule](/object-storage/storage-classes/lifecycle-rules/) that transitions objects to Glacier after a defined delay. See [When lifecycle transitions apply](/object-storage/storage-classes/understanding-storage-classes/#when-lifecycle-transitions-apply) for the timing of these transitions.

## Restore objects from Glacier

To download an object stored in Glacier, you must first [restore it](/object-storage/storage-classes/restore-from-glacier/). Restores have the following constraints:

- You can only restore an object to the Standard Multi-AZ class. You cannot restore it to Standard One Zone.
- You cannot use a lifecycle rule to restore objects from Glacier.
- A restore is not instantaneous. For objects larger than 1 MB, it can take from a few minutes to 24 hours for the restore to start.

The restore time depends on the size of the object and on whether you uploaded it with [multipart uploads](/object-storage/concepts/glossary/#multipart-uploads). Scaleway cannot provide an estimate of the retrieval time for each use case.

## Encrypt data stored in Glacier

For increased security, Scaleway recommends encrypting your data before you send it to Glacier. Client-side encryption guarantees that your private key is never stored on the cluster.

You can encrypt data with third-party tools such as [GPG](https://gnupg.org/), or automate encrypted backups with [Duplicity](https://wiki.debian.org/Duplicity) or [rclone crypt](https://rclone.org/crypt/). See [Understanding encryption](/object-storage/data-protection/understanding-encryption/) for all encryption methods.

## Manage GDPR storage and archiving constraints

The GDPR requires that you define the lifespan of data in the following cases:

- The deletion of data after a certain period of time
- The archiving of data that must legally be kept

[Lifecycle rules](/object-storage/storage-classes/lifecycle-rules/) meet both requirements, by letting you set a time frame after which Object Storage archives or deletes your data.
