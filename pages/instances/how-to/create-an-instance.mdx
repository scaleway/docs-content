An [Instance](/instances/concepts/#instance) is a virtual machine in the cloud. Like a physical machine, it provides resources such as virtualized CPU, RAM, and storage. These resources depend on the [Instance type](/instances/reference-content/choosing-instance-type/) you choose. After you create an Instance, you can [connect to it](/instances/how-to/connect-to-instance/) and use it for small-scale tests, personal projects, development environments, application hosting, or production workloads.

You can create an Instance from scratch or from an Instance template. The procedures on this page create an Instance from scratch. See [Create and manage Instance templates](/instances/how-to/create-manage-instance-templates/) for more information.

The following tabs describe how to create an Instance using the [console](https://console.scaleway.com), the [Instances API](https://www.scaleway.com/en/developers/api/instances/), or the [Scaleway CLI](https://github.com/scaleway/scaleway-cli).

<Tabs>
  <TabsTab label="Console - Linux">
    <Requirements />

    - A Scaleway account logged in to the [console](https://console.scaleway.com)
    - [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
    - An [SSH key](/iam/security/create-ssh-key/)

    1. In the Scaleway console side menu, go to **Compute** > **CPU & GPU Instances**. The [Instances dashboard](https://console.scaleway.com/instance/servers) opens.
    2. Click **Create Instance** > **Create CPU Instance**. The Instance creation wizard opens.
    3. Select an Instance range that matches your usage. Instance offers vary in pricing, processing power, memory, storage, and bandwidth. See [Choosing an Instance type](/instances/reference-content/choosing-instance-type/) for more information.
    4. Choose an Instance configuration from the list, then click **Select**. A dialog box appears.
    5. Select the Availability Zone in which to deploy your Instance, then click **Configure Instance**.
    6. Enter a name for your Instance, or keep the randomly generated name. Optionally, add [tags](/instances/concepts/#tags) to organize your Instances.
    7. Choose an image to run on your Instance. The image can be an operating system, an InstantApp, or a custom image. See [Linux distributions and InstantApps](/instances/reference-content/images-and-instantapps/), for the list of available images.
    8. Configure the volumes of your Instance. Scaleway automatically creates a system volume on Block Storage, with a default name and 5,000 input/output operations per second (IOPS). You can customize this volume and attach up to 16 local or block volumes.

        <Message type="important">
          - The volume that contains the OS image must be at least 10 GB. For a GPU OS, Scaleway recommends 125 GB.
          - If you attach several Block Storage volumes, the primary volume hosts the OS and is required to boot the Instance. You can [change the boot volume](/instances/how-to/use-boot-modes/#how-to-change-the-boot-volume) after creation.
          - Do not boot from a volume with no OS, or from one of several volumes that share the same OS. The boot behavior is unpredictable.
        </Message>

    9. Configure the public IP addresses of the Instance. By default, the **Public IPv4** and **Public IPv6** options are enabled. For each option, allocate a new address, select one or several existing addresses, or disable the option if you do not want this type of address.

        You can attach up to 5 IPv4 and five IPv6 addresses to an Instance, for example to run different services or applications on the same Instance.
    10. Select the **Security group** to apply to the public traffic of the Instance, or keep the default security group of the Availability Zone.
    11. (Optional) Connect the Instance to a [Private Network](/instances/concepts/#private-networks):
        1. Select **Attach to Private Network**.
        2. Select the **VPC** and the **Private Network**.
        3. Keep **Auto-allocate a Private Network interface** to create a new [Private Network interface](/instances/concepts/#private-network-interface), or select an existing Private Network interface that is not attached to any Instance.
        4. (Optional) Select a **Security group** to filter the Private Network traffic of the Instance. The security group must be [stateful](/instances/concepts/#stateful-security-groups). You can use the same security group for public and private traffic, or a different one for each.
        5. Choose the **Private IPv4 address** and the **Private IPv6 address** of the Instance on the Private Network. You can auto-allocate an available IP address or use a [reserved IP address](/ipam/concepts/#reserved-ip-address).
    12. (Optional) Click **Cloud-init** to add a [cloud-init configuration](/instances/concepts/#cloud-init), or keep the default value. Cloud-init scripts automate Instance setup at first boot, such as installing software or configuring users and system settings.
    13. Check the [SSH keys](/organizations-and-projects/concepts/glossary/#ssh-key) that give you access to your Instance.
    14. Click **Review**. An order summary opens, with the estimated cost of your Instance based on the specifications you chose.
    15. Click **Create Instance**, or click **Create Instance and save as template** to also save this configuration as a template. See [Create and manage Instance templates](/instances/how-to/create-manage-instance-templates/) for more information.

        The Instance starts provisioning, and the **Overview** tab of the Instance opens. A notification appears when the Instance is ready. The **Overview** tab shows the public IP address of the Instance, the SSH command to [connect to it](/instances/how-to/connect-to-instance/), and other information, settings, and actions.
  </TabsTab>

  <TabsTab label="Console - Windows">
    <Requirements />

    - A Scaleway account logged in to the [console](https://console.scaleway.com)
    - [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
    - An [RSA key pair](/iam/security/create-ssh-key/#how-to-generate-a-rsa-ssh-key-pair)

    1. In the Scaleway console side menu, go to **Compute** > **CPU & GPU Instances**. The [Instances dashboard](https://console.scaleway.com/instance/servers) opens.
    2. Click **Create Instance** > **Create CPU Instance**. The Instance creation wizard opens.
    3. Select an Instance range that matches your usage. Instance offers vary in pricing, processing power, memory, storage, and bandwidth. See [Choosing an Instance type](/instances/reference-content/choosing-instance-type/) for more information.
    4. Choose a **Windows Instance** type from the **General Purpose** range, then click **Select**. A dialog box appears.
    5. Select the Availability Zone in which to deploy your Instance, then click **Configure Instance**.
    6. Enter a name for your Instance, or keep the randomly generated name. Optionally, add [tags](/instances/concepts/#tags) to organize your Instances. To enable OpenSSH Server on the Instance at creation, add the `with-ssh` tag.
    7. Choose a Windows image to run on your Instance.
    8. Configure the volumes of your Instance. Scaleway automatically creates a system volume on Block Storage, with a default name and 5,000 input/output operations per second (IOPS). You can customize this volume and attach up to 16 local or block volumes.

        <Message type="important">
          - The volume that contains the Windows Server image must be at least 25 GB.
          - If you attach several Block Storage volumes, the primary volume hosts the OS and is required to boot the Instance. You can [change the boot volume](/instances/how-to/use-boot-modes/#how-to-change-the-boot-volume) after creation.
          - Do not boot from a volume with no OS, or from one of several volumes that share the same OS. The boot behavior is unpredictable.
        </Message>

        To use [Block Storage Low Latency 15k](/block-storage/), your Instance must provide at least 3 GiB/s of block bandwidth. See [Instances internet and Block Storage bandwidth overview](/instances/reference-content/instances-bandwidth-overview/), to check whether an Instance type meets this requirement. You can also check the `block_bandwidth` field returned by the [List Instance types](https://www.scaleway.com/en/developers/api/instances/#path-instance-types-list-instance-types) endpoint (`/instance/v1/zones/{zone}/products/servers`) of the Instances API. This field gives the exact block bandwidth of each Instance type.
    9. Configure the public IP addresses of the Instance. By default, the **Public IPv4** and **Public IPv6** options are enabled. For each option, allocate a new address, select one or several existing addresses, or disable the option if you do not want this type of address.

        You can attach up to five IPv4 and five IPv6 addresses to an Instance, for example to run different services or applications on the same Instance.
    10. Select the **Security group** to apply to the public traffic of the Instance, or keep the default security group of the Availability Zone.
    11. (Optional) Connect the Instance to a [Private Network](/instances/concepts/#private-networks):
        1. Select **Attach to Private Network**.
        2. Select the **VPC** and the **Private Network**.
        3. Keep **Auto-allocate a Private Network interface** to create a new [Private Network interface](/instances/concepts/#private-network-interface), or select an existing Private Network interface that is not attached to any Instance.
        4. Optionally, select a **Security group** to filter the Private Network traffic of the Instance. The security group must be [stateful](/instances/concepts/#stateful-security-groups). You can use the same security group for public and private traffic, or a different one for each.
        5. Choose the **Private IPv4 address** and the **Private IPv6 address** of the Instance on the Private Network. You can auto-allocate an available IP address or use a [reserved IP address](/ipam/concepts/#reserved-ip-address).
    12. Optionally, click **Advanced options** to add a [cloud-init configuration](/instances/concepts/#cloud-init), or keep the default values. Cloud-init scripts automate Instance setup at first boot, such as installing software or configuring users and system settings.
    13. Choose the [RSA SSH key](/iam/security/create-ssh-key/#how-to-generate-a-rsa-ssh-key-pair) that gives you access to your Instance. If you do not have an RSA SSH key, click **Add RSA SSH key** and follow the steps.
    14. Click **Review**. An order summary opens, with the estimated cost of your Instance based on the specifications you chose.
    15. Click **Create Instance**, or click **Create Instance and save as template** to also save this configuration as a template. See [Create and manage Instance templates](/instances/how-to/create-manage-instance-templates/) for more information.

        The Instance starts provisioning, and the **Overview** tab of the Instance opens. A notification appears when the Instance is ready. The **Overview** tab shows the public IP address of the Instance, the SSH command to [connect to it](/instances/how-to/connect-to-instance/), and other information, settings, and actions.
  </TabsTab>
  
  <TabsTab label="API">
    <Requirements />

    - A Scaleway account logged in to the [console](https://console.scaleway.com)
    - [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
    - An [SSH key](/iam/security/create-ssh-key/)
    - A valid [API key](/iam/credentials/create-api-keys/)
    - [`curl`](https://curl.se/) installed on your local machine

    <Message type="tip">
      To format and parse API responses, install [`jq`](https://jqlang.org/) and append `| jq .` to any `curl` command.
    </Message>

    1. In a terminal, export the following environment variables. Replace the placeholders with your own values:
        - `<API_ACCESS_KEY>` and `<API_SECRET_KEY>`: the [access key and secret key](/iam/concepts/glossary/#api-key) of your API key.
        - `<PROJECT_ID>`: the ID of the [Project](/iam/concepts/glossary/#project) in which to create the Instance. You can find it in the [**Settings** tab](https://console.scaleway.com/project/settings) of the Project in the Scaleway console.
        - `<AVAILABILITY_ZONE>`: the [Availability Zone](/instances/concepts/#availability-zone) in which to create the Instance, such as `fr-par-1`.

        ```bash
        export SCW_ACCESS_KEY="<API_ACCESS_KEY>"
        export SCW_SECRET_KEY="<API_SECRET_KEY>"
        export SCW_PROJECT_ID="<PROJECT_ID>"
        export SCW_DEFAULT_ZONE="<AVAILABILITY_ZONE>"
        export PAYLOAD_FILE_PATH="/tmp/payload.json"
        ```
    2. Run the following command to list the available images, and note the `label` of the OS image you want to use.

        ```bash
        curl --location "https://api.scaleway.com/marketplace/v2/images" \
          --header "X-Auth-Token: $SCW_SECRET_KEY"
        ```

        The response lists the available images, with their `label`:

        ```json
        {
          "images": [
            {
              "id": "607b12c2-685d-45f7-905f-57bc23863834",
              "name": "Ubuntu 24.04 Noble Numbat",
              "label": "ubuntu_noble",
              ...
            },
          ],
          "total_count": 23
        }
        ```
    3. Create a payload file that defines the configuration of the Instance. The following example contains all required parameters. Use the table below to adapt it to your needs.

        ```bash
        cat <<EOF > "$PAYLOAD_FILE_PATH"
        {
          "name": "my-new-instance",
          "project": "$SCW_PROJECT_ID",
          "commercial_type": "GP1-S",
          "image": "ubuntu_noble",
          "volumes": {
            "0": {
              "name": "my-volume",
              "size": 300000000000,
              "volume_type": "l_ssd"
            }
          }
        }
        EOF
        ```

        | Parameter         | Description                                          | Valid values |
        |-------------------|------------------------------------------------------|--------------|
        | `name`            | A name of your choice for the Instance (string)      | Any string that contains only alphanumeric characters, dots, spaces, and dashes, e.g., `"my-new-instance"` |
        | `project`         | The Project in which to create the Instance (string) | Any valid Scaleway Project ID, e.g., `"b4bd99e0-b389-11ed-afa1-0242ac120002"` |
        | `commercial_type` | The commercial Instance type to create (string)      | Any valid ID of a Scaleway commercial Instance type, e.g., `"GP1-S"` or `"PRO2-M"`. To get all valid Instance types and their IDs, use the [List Instance types](https://www.scaleway.com/en/developers/api/instances/#path-instance-types-list-instance-types) endpoint. |
        | `image`           | The image to install on the Instance, such as an OS (string) | Any valid Scaleway image label, e.g., `ubuntu_noble` for the Ubuntu 24.04 Noble Numbat image |
        | `volumes`         | The storage volumes to attach to the Instance (object). The volumes must respect the volume constraints of the `commercial_type`: each Instance type has a minimum and a maximum amount of storage, and some Instance types support only Block Storage (`sbs_volume`). To find these constraints, check the `volume_constraints` field of each type returned by the [List Instance types](https://www.scaleway.com/en/developers/api/instances/#path-instance-types-list-instance-types) endpoint. | An object with at least one key (`"0"`). Each key contains `name` (the volume name), `size` (the volume size, in bytes), and `volume_type` (`l_ssd` or `sbs_volume`). Increment the key by one for each additional volume (`"1"` for the second volume). You can also attach existing volumes or create a volume from a snapshot. See [Volumes](https://www.scaleway.com/en/developers/api/instances/#path-volumes) in the Instances API documentation, for more information. |

    4. Run the following command to create the Instance with your payload file.

        ```bash
        curl -X POST -H "Content-Type: application/json" \
          -H "X-Auth-Token: $SCW_SECRET_KEY" \
          "https://api.scaleway.com/instance/v1/zones/${SCW_DEFAULT_ZONE}/servers" \
          -d @"$PAYLOAD_FILE_PATH"
        ```

        If the request succeeds, the API returns a `201` response with a `server` object that contains the attributes of your Instance.

    An Instance created with the API has no public connectivity by default. To make it reachable from the internet, attach an IP address to it. See [How to use flexible IP addresses with Instances](/instances/how-to/use-flexips/), for more information.

    The Instance is also powered off by default. To power it on, call the [Perform action](https://www.scaleway.com/en/developers/api/instances/#path-instances-perform-action) endpoint with the ID of your Instance, returned in the `201` response, and `poweron` as the `action`.

    See the [Instances API documentation](https://www.scaleway.com/en/developers/api/instances/), and the [Create an Instance](https://www.scaleway.com/en/developers/api/instances/#path-instances-create-an-instance) page for all configurable parameters.

  </TabsTab>

  <TabsTab label="CLI">
    <Requirements />

    - A Scaleway account logged in to the [console](https://console.scaleway.com)
    - [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
    - An [SSH key](/iam/security/create-ssh-key/)
    - A valid [API key](/iam/credentials/create-api-keys/)
    - The [Scaleway CLI](https://github.com/scaleway/scaleway-cli) installed and configured on your local machine

    1. Run the following command to list the available images, and note the label of the OS image you want to use.

        ```bash
        scw marketplace image list
        ```

        The output lists the available images, with their label:

        ```text
        ID                                    LABEL                     NAME                          CATEGORIES          VALID UNTIL
        607b12c2-685d-45f7-905f-57bc23863834  ubuntu_noble              Ubuntu 24.04 Noble Numbat     [distribution]      -
        ```

    2. Choose a value for each of the following parameters to define your Instance. Use the table below to select appropriate values.

        ```text
        name=my-new-instance
        project-id=<PROJECT_ID>
        zone=fr-par-1
        type=GP1-S
        image=ubuntu_noble
        ip=new
        root-volume=l:300GB
        ```

        | Parameter     | Description                                          | Valid values |
        |---------------|------------------------------------------------------|--------------|
        | `name`        | A name of your choice for the Instance               | Any string that contains only alphanumeric characters, dots, spaces, and dashes, e.g., `my-new-instance` |
        | `project-id`  | The Project in which to create the Instance          | Any valid Scaleway Project ID, e.g., `b4bd99e0-b389-11ed-afa1-0242ac120002` |
        | `zone`        | The Availability Zone in which to create the Instance. Some Instance types are only available in certain Availability Zones (see `type`). | Any valid Scaleway Availability Zone, e.g., `fr-par-1` or `pl-waw-2` |
        | `type`        | The type of Instance to create                       | Any valid ID of a Scaleway Instance type, e.g., `GP1-S` or `PRO2-M`. To get all valid Instance types and their IDs, use the [server-type](https://github.com/scaleway/scaleway-cli/blob/master/docs/commands/instance.md#server-type-management-commands) command. The default value is `DEV1-S`. |
        | `image`       | The image to install on the Instance, such as an OS  | Any valid Scaleway image label, e.g., `ubuntu_noble` for the Ubuntu 24.04 Noble Numbat image |
        | `ip`          | The IP address to use for the Instance               | `new` to create a new IP address, `dynamic` to create a dynamic IP address, `none` for no public IP address, or the ID of an existing IP address. The default value is `new`. |
        | `root-volume` | The root volume of the Instance: the volume type (`l` for local or `b` for block), followed by a colon and the volume size, e.g., `l:10GB` | Any valid volume type and size consistent with the storage constraints of the Instance `type`. To find these constraints, run `scw instance server-type list`. |

    3. Run the following command, with the parameter values you chose in step 2.

        ```bash
        scw instance server create name=my-new-instance project-id=<PROJECT_ID> zone=fr-par-1 type=GP1-S image=ubuntu_noble ip=new root-volume=l:300GB
        ```

        The CLI creates the Instance and returns its details.

    See the [Scaleway CLI Instance documentation](https://github.com/scaleway/scaleway-cli/blob/master/docs/commands/instance.md), for all available parameters and next steps.
