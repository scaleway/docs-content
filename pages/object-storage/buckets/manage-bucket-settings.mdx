A bucket has settings that apply to all the objects it contains, such as visibility, versioning, encryption, and access rules. You can configure most of them from the **Bucket settings** tab of the bucket in the [Scaleway console](https://console.scaleway.com), and all of them with the Amazon S3 API and compatible tools. This page lists the available settings, and links to the page that describes each one.

<Requirements />

- A Scaleway account logged into the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
- An [Object Storage bucket](/object-storage/buckets/create-a-bucket/)

## Open the settings of a bucket

1. In the Scaleway console side menu, under **Storage**, click **Object Storage**. The list of your buckets appears.

2. Click the name of the bucket.

3. Click the **Bucket settings** tab.

## Available bucket settings

### General settings

| Setting | Description | Console | API/CLI | Documentation |
|---|---|---|---|---|
| Visibility | Whether anyone can list the objects of the bucket | Yes | Yes | [How to manage object visibility and sharing](/object-storage/access-control/object-visibility-and-sharing/) |
| Tags | Key-value pairs attached to the bucket, which you can use in lifecycle rule filters | No | Yes | [PutBucketTagging](/object-storage/api-clients/bucket-operations/#putbuckettagging) |

### Data protection

| Setting | Description | Console | API/CLI | Documentation |
|---|---|---|---|---|
| Versioning | Keeps several versions of each object | Yes | Yes | [How to use bucket versioning](/object-storage/data-protection/versioning/) |
| Object lock | Prevents objects from being deleted or overwritten for a retention period. Requires versioning. | Yes | Yes | [How to use object lock](/object-storage/data-protection/object-lock/) |
| Default encryption | Encrypts new objects at rest with SSE-ONE or SSE-KMS | Yes | Yes | [Understanding encryption](/object-storage/data-protection/understanding-encryption/) |

### Access control

| Setting | Description | Console | API/CLI | Documentation |
|---|---|---|---|---|
| Bucket policy | Defines which principals can perform which actions on the bucket and its objects | Yes | Yes | [How to manage bucket policies](/object-storage/access-control/manage-bucket-policies/) |
| CORS rules | Define which web domains can send requests to the bucket from a browser | No | Yes | [Manage CORS rules on Object Storage buckets](/object-storage/access-control/cors/) |

### Data management

| Setting | Description | Console | API/CLI | Documentation |
|---|---|---|---|---|
| Lifecycle rules | Transition objects to colder storage classes, expire objects, and abort incomplete multipart uploads automatically | Yes | Yes | [How to manage lifecycle rules](/object-storage/storage-classes/lifecycle-rules/) |
| Bucket website | Hosts a static website on the bucket | Yes | Yes | [How to host a static website on a bucket](/object-storage/buckets/bucket-website/) |

## Other bucket operations

- [Monitor the usage of the bucket](/object-storage/optimization-monitoring/monitor-usage/) from its **Metrics** and **Logs** tabs.
- [Migrate data](/object-storage/buckets/migrate-data/) from one bucket to another.
- [Delete the bucket](/object-storage/buckets/delete-a-bucket/) from the bottom of the **Bucket settings** tab.

For the full list of bucket API operations, see [Understanding Object Storage bucket operations](/object-storage/api-clients/bucket-operations/).
