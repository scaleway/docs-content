Data Orchestrator in Code view requires that you upload a YAML file to use as a workflow definition.

This page lists the action tasks specifically developed for Data Orchestrator workflow definitions.
Data Orchestrator is based on the [Serverless workflow.io](https://serverlessworkflow.io/) standard. For more information on other action tasks, see the [Open Workflow DSL Reference](https://github.com/open-workflow-specification/specification/blob/main/dsl-reference.md).

<Message type="note">
  Replace the placeholders of the following examples with the appropriate values.
  The `namespace` and `name` fields are required. You can use them as metadata to help organize your YAML files.
</Message>

<Tabs>
  <TabsTab label="Serverless Job">
    This is an example of a workflow calling one Serverless Job. You can copy Serverless Job IDs from the [Serverless Jobs page](https://console.scaleway.com/serverless-jobs/) of the console.

    <Message type="important">
      The workflow and the Serverless Job must be in the same project.
    </Message>

      ```yaml
      document:
        dsl: 1.0.3
        namespace: <namespace_name>
        name: <workflow_name>
        version: 1.0.0
      do:
        - callServerlessJob:
            call: "serverless_job"
            metadata:
              description: "The first job"
            with:
              id: "<Serverless_job_ID>"
              region: "fr-par"
      ```
  </TabsTab>

  <TabsTab label="Serverless Function">
    The Serverless Function call allows you to call the default endpoint of your Serverless Functions.
    
    Instead of using an HTTP endpoint (with potential authentication), this call uses the function identifier (`id`) and region (`region`) to invoke it, and handles authentication for you.
    
    This is an example of a how to get a Serverless Function. You can copy Serverless Function IDs from the [Serverless Functions page](https://console.scaleway.com/functions/) of the console.

    <Message type="important">
      The workflow and the Serverless Function must be in the same project.
    </Message>

      ```yaml
      document:
        dsl: 1.0.3
        namespace: <namespace_name>
        name: <workflow_name>
        version: 1.0.0
      do:
        - callServerlessFunction:
            call: "serverless_function"
            with:
              method: GET
              id: "<Serverless_function_ID>"
              region: "fr-par"
              output: "response"    
      ```
  </TabsTab>
  
  <TabsTab label="Serverless Container">
    The Serverless Container call allows you to call the default endpoint of your Serverless Containers.
    
    Instead of using an HTTP endpoint (with potential authentication), this call uses the container identifier (`containerdId`) or the container name (`name`) + namespace identifier (`namespaceName` or `namespaceId`) and region (`region`) to invoke it, and handles authentication for you.
    
    This is an example of a how to get a Serverless Container. you can copy Serverless Container IDs from the [Serverless Containers page](https://console.scaleway.com/containers/) of the console.
    <Message type="important">
      The workflow and the Serverless Container must be in the same project.
    </Message>

      ```yaml
      document:
        dsl: 1.0.3
        namespace: <namespace_name>
        name: <workflow_name>
        version: 1.0.0
      do:
        - callServerlessContainer:
            call: "serverless_container"
            with:
              method: GET
              id: "<Serverless_container_ID>"
              region: "fr-par"
              output: "response"
      ```
  </TabsTab>

  <TabsTab label="HTTP Call">
    The HTTP call allows you to call any external service over HTTP.
    This is an example of a how to make an HTTP call.

      ```yaml
      document:
        dsl: 1.0.3
        namespace: <namespace_name>
        name: <workflow_name>
        version: 1.0.0
      do:
        - httpCall:
            call: "http"
            with:
              method: GET
              url: "<url>"
              output: "response"
      ```
  </TabsTab>
</Tabs>

## Properties

<Tabs>
  <TabsTab label="Serverless Job">
    **Workflow definition properties**

    | Property&nbsp;name |  Type  | Required |                   Description                   |
    | :----------------- | :----- | :------- | :---------------------------------------------- |
    | `id`               | string | yes      | The ID of the Serverless Job                    |
    | `region`           | string | yes      | The region where the Serverless Job is deployed. Supported values: `fr-par`, `nl-ams`, or `pl-waw`. |
  </TabsTab>

    | `region`           | string           | yes      | The region where the Serverless Function is deployed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
