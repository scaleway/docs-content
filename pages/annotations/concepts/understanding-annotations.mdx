[Scaleway Annotations](/annotations/) lets you attach custom key-value metadata to your Scaleway cloud resources, such as Kubernetes clusters, Block Storage volumes, or Managed Databases. Using Annotations, you can organize and structure your resources for use in FinOps, GreenOps, governance, and other applications.

An [annotation](/annotations/concepts/glossary/#annotation) consists of a [key](/annotations/concepts/glossary/#key) and a [value](/annotations/concepts/glossary/#value). Keys and values are stored once in a centralized dictionary and can then be bound to one or more of your resources via their [Scaleway Resource Names (SRNs)](/annotations/reference-content/scaleway-resource-names/). This centralized, structured approach makes Annotations suitable for cross-product organization, cost tracking, impact tracking, reporting, auditing, and automation.

This page provides a general overview of Annotations. See the [Annotations Quickstart](/annotations/quickstart/) for an introduction on using the product.

## How Annotations work

Annotations is built around the following main elements:

**Key**
: A globally unique identifier that names the piece of metadata you want to attach to a resource. It defines the category of information for a resource, for example `Team`, `Environment`, or `Cost-center`.

**Value**
: The concrete information associated with a key, for example `Marketing`, `Production`, or `83546`. A value cannot exist on its own; it must always belong to a key.

**Binding**
: The explicit association that links an annotation (a key-value pair) to a specific resource. When you bind an annotation to a resource, you associate one of its values with the resource using the SRN of the resource.

**Scaleway Resource Name (SRN)**
: The Uniform Resource Identifier (URI) used to target the resource you want to bind an annotation to.

## Why use Annotations

Annotations gives you a lightweight, flexible way to add structured metadata to your Scaleway resources, making it easier to search, manage, audit, and optimize them.

### Navigation and filtering

Annotate resources so you can filter and search them by any custom attribute. When you have hundreds of resources, filtering by annotation lets you quickly locate the subset you need.

| Key | Example values | What it helps you find |
|---|---|---|
| `environment` | `dev`, `staging`, `prod` | All resources in a given environment |
| `team` | `payments`, `infra`, `data` | Everything owned by a specific team |
| `owner` | `jane.doe`, `ops-team` | Resources a person or team is responsible for |

### Governance

Combine annotations with IAM or policy bindings to restrict actions on resources that carry certain annotations (e.g., only the `security` team can modify resources marked `sensitive=true`).

### FinOps: Cost tracking and reporting

Use annotations to break down cloud spend across teams, projects, or clients.

| Key | Example values | What it helps you track |
|---|---|---|
| `cost_center` | `CC-4021`, `CC-7710` | Spend per internal cost center |
| `client` | `acme-corp`, `globex` | Billable spend per client |
| `project` | `migration-2026`, `refactor-api` | Spend per project or initiative |

### GreenOps: Environmental tracking

Use annotations to attribute and reduce the carbon and water footprint of your workloads. Pair annotation keys with the [Environmental Footprint](/environmental-footprint/) dashboard to see consumption broken down by team, project, or business unit — and to target optimization efforts where they matter most.

| Key | Example values | What it helps you track |
|---|---|---|
| `cost_center` | `CC-4021`, `CC-7710` | Footprint per internal cost center |
| `team` | `payments`, `infra`, `data` | Carbon/water usage per team |
| `project` | `migration-2026`, `refactor-api` | Impact per project or initiative |
| `greenops_status` | `baseline`, `optimized`, `pending` | Progress of your reduction efforts |

### Workflow automation

Trigger scripts, policies, or scaling actions based on specific annotation values (e.g., automatically back up all resources with the annotation `environment=prod`).

## Access control

To use Annotations, you configure a dedicated permission set in IAM to control access to keys, values, and bindings:

- `AnnotationsFullAccess`: Full access to annotation keys, values, and bindings.
- `AnnotationsReadOnly`: Read-only access to annotations. Typical users are auditors or finance team members.
- `AnnotationsBindingManager`: Allows attaching annotations to resources, without the ability to modify the annotation dictionary.

Learn how to set up [Annotations permission sets](/annotations/setup-lifecycle/configure-annotations-permissions/).

## Technical rules and limits

Specific validation and integrity rules apply when you create or manage annotation keys, values, and bindings. For example, a resource can only have one value per key, and the number of keys, values, and bindings you can create is subject to quotas. Review the full list in the [Technical rules and limits](/annotations/reference-content/technical-rules-limits/) reference documentation.
