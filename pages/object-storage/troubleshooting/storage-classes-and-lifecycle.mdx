- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization

## I cannot restore my objects from Glacier

You need to retrieve your data from the Glacier storage class, but the [restore operation](/object-storage/how-to/restore-an-object-from-glacier/) does not seem to work.

### Cause

The time it takes to restore an object depends on the size of the object, and on whether it was uploaded using [multipart upload](/object-storage/concepts/#multipart-uploads). If your object is larger than 1 MB, the restore can take from a few minutes to 24 hours to start.

### Solution

1. Run the following command in a terminal to retrieve the metadata of the object you want to restore:
    ```bash
    aws s3api head-object --bucket <BUCKET_NAME> --key <OBJECT_NAME>
    ```
    An output similar to the following is displayed:
    ```json no-copy
    {
        "AcceptRanges": "bytes",
        "Restore": "ongoing-request=\"true\"",
        "LastModified": "2024-03-13T16:30:44+00:00",
        "ContentLength": 5,
        "ETag": "\"sd11r084349bc25d97e29393ced1d\"",
        "ContentType": "application/octet-stream",
        "Metadata": {},
        "StorageClass": "GLACIER"
    }
    ```
2. Check the `Restore` line. `"Restore": "ongoing-request=\"true\""` indicates that the restore operation has already started. Wait for it to complete.

## My lifecycle rules do not work as expected

Your [lifecycle rules](/object-storage/how-to/manage-lifecycle-rules/) do not transition or expire objects as expected.

### Cause

- The lifecycle rules are not properly set.
- The prefixes or tags of your objects contain spaces.
- You reached the limit of 500,000 lifecycle jobs per day.

### Solution

- Make sure that your [lifecycle rules are properly set](/object-storage/how-to/manage-lifecycle-rules/) in the Scaleway console.
- Make sure that the prefixes and tags of your objects do not contain any spaces.
- If you reached the limit of 500,000 jobs per day, [transition](/object-storage/how-to/edit-storage-class/) or [delete](/object-storage/how-to/delete-an-object/) objects manually.
- For expiration rules, use the [HeadObject](/object-storage/api-cli/object-operations/#headobject) command to check which rule applies to a specific object. The `x-amz-expiration` header returns the expiration date and rule ID.

## Going further

- See the [lifecycle rules API documentation](/object-storage/api-cli/lifecycle-rules-api/) for more information on lifecycle configuration elements.
- When you contact the Support team about Object Storage, include the endpoint (e.g., `s3.fr-par.scw.cloud`), the bucket name, and the object name if the request concerns an object.
