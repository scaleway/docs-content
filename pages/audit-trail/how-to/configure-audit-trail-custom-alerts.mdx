Audit Trail Alerting Management lets you proactively monitor the actions performed on your Scaleway resources. You can [enable a set of preconfigured alerts](/audit-trail/how-to/activate-adt-preconfigured-alerts) or configure custom alerts based on your security and monitoring needs so Audit Trail notifies you of abnormal or sensitive behavior. This page explains how to set custom alerts.

<Requirements />

- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to view and manage Audit Trail

<Message type="note">
  Events related to global products which are not region-specific (such as IAM, Account, or Edge Services activities) are considered FR-PAR (Paris) events.
</Message>


## Configure a custom alert

<Message type="note">
  After creating an alert, you can edit only the name and description of the alert.
</Message>

1. In the [Scaleway console](https://console.scaleway.com/) side menu, go to **Monitoring** > **Audit Trail**.
2. Click the **Region** dropdown and select the region for which you want to create alerts.
3. Click the **Alerts** tab, then select **Custom**.
4. Click **Create alert**. The alert creation wizard opens.
5. Add a name and description for the alert.
6. Set a severity (e.g., info, error, warning).
7. Define a rule for the alert, using the visual builder or the code editor. The steps here assume that you are using the visual builder. For details on the code editor, see [Use the code editor and CEL expressions](#use-the-code-editor-and-cel-expressions).

    1. Select the type of event that you want to be alerted on (e.g., an event related to a product (**Product name**), an action (**Method name**), and so on).
    2. Select a function (**is** or **is not**).
    3. Select an event value from the dropdown (e.g., **Instance**, **CreateAPIKey**) or type a value in the freeform field.

    For example, you can set up an alert that fires when users are deleted.

    <Lightbox image={image1} alt="A screenshot showing the custom alert creation wizard of the Scaleway console, the part where you can define a rule for an alert." size="medium" />
8. If your alert requires multiple rules, click **+ Add** to add another rule.
9. Configure the condition that will trigger the alert:
    1. Set **Occurrence**, that is, the number of times the condition must be satisfied to trigger the alert. 
    
          For example, you can create an alert that triggers when 5 or more users are deleted in a short time (the deletion event occurs at least 5 times). In this case, you would set **Occurrence** to **5**.

    2. Set **Timeframe**, that is, the time window in which the condition must be evaluated. 
    
          For example, you can set up an alert to trigger whenever 5 or more users are deleted within a 10-minute time window. In this case, you would set **Timeframe** to **10**.
10. Click **Test alert** to check if:
    - the syntax of your alert configuration is valid
    - there are currently any active events that match the alert rule you defined
11. Once your configuration syntax is valid, click **Create custom alert**. On succesful creation, the **Overview** page of your alert opens, showing the details of your new active alert.

### Use the code editor and CEL expressions

If you wish to define a custom alert by writing the alert expression yourself, use the code editor. The code editor uses the Common Expression Language (CEL). CEL lets you create expressions that define the events that you want to be alerted about.

    <Message type="note">
      Changing from the code editor to the visual builder while creating a rule discards all details already defined for the rule.
    </Message>

Example CEL expression for an alert that is triggered when delete operations are executed from a specific IP address:

```bash
(methodName.startsWith("Delete") && sourceIp == "192.0.2.1")
```

Your alert expression is made up of:
- event types
- operators and/or functions
- event values 

| Event types   | Operators / Functions    |
| -------- | ----------- |
| The following event types are supported: <br/><br/>- `method_name` <br/> - `principal_id` <br/>- `product_name` <br/>- `project_id` <br/>- `resource_id` <br/>- `service_name` <br/>- `source_ip` <br/>- `status` | Operators and functions can include the following: <br/><br/>- **Equality and inequality operators** (defined for all types): `==`, `!=` <br/>Examples: `method_name == "GetKey"`, `status != 200` <br/><br/>- **Comparison operators** (only for integers): `<=`, `<`, `>`, `>=` <br/>Example: `status > 400` <br/><br/>- **Logical `AND` operator**: `&&` <br/>Example: `method_name == "GetKey" && status != 200` <br/><br/>- **String functions** (only for strings): `contains`, `matches`, `startsWith`, `endsWith` <br/>Example: `method_name.contains("Delete"), source_ip.matches("127.0.*.1")` | 


## Enable or disable a custom alert

You can enable or disable an existing custom alert in the following ways:
- from the **Overview** page of the custom alert
- from the **Alert** tab listing all your custom alerts (use this option to batch enable/disable multiple alerts at the same time)

<Message type="note">
  Charges apply even when a custom alert is disabled.
</Message>

To enable or disable an existing alert from its **Overview** page, follow these steps:

1. In the [Scaleway console](https://console.scaleway.com/) side menu, go to **Monitoring** > **Audit Trail**.
2. Click the **Region** dropdown and select the region where the alert has been created.
3. Click the **Alerts** tab, then click **Custom**.
4. Click <Icon name="more" /> next to the alert that you want to enable/disable and select **More info**. The **Overview** page of the alert opens.
5. Go to the **Manage alert** section and use the toggle to enable or disable your alert.

To enable or disable one or more existing alerts, use the **Alert** tab listing all your custom alerts:

1. In the [Scaleway console](https://console.scaleway.com/) side menu, go to **Monitoring** > **Audit Trail**.
2. Click the **Region** dropdown and select the region where the alert has been created.
3. Click the **Alerts** tab, then click **Custom**.
4. Check or uncheck **Enabled** to enable or disable your alert(s).
5. Click **Save changes** at the bottom of the page to apply your configuration. A dialog box appears, confirming the action you are about to take. Click **Save changes** again.

## Duplicate a custom alert to another region

1. In the [Scaleway console](https://console.scaleway.com/) side menu, go to **Monitoring** > **Audit Trail**.
2. Click the **Region** dropdown and select the region where the alert has been created.
3. Click the **Alerts** tab, then click **Custom**.
4. Click <Icon name="more" /> next to the alert that you want to enable/disable and select **Duplicate to other region(s)**. A dialog box opens.
5. Review the details of the alert, select the **Destination region**, and click **Duplicate**.

## Delete a custom alert

1. In the [Scaleway console](https://console.scaleway.com/) side menu, go to **Monitoring** > **Audit Trail**.
2. Click the **Region** dropdown and select the region where the alert has been created.
3. Click the **Alerts** tab, then click **Custom**.
4. Click <Icon name="more" /> next to the alert that you want to delete and select **Delete**. A dialog box opens.
5. Type `DELETE` and click **Delete alert** to confirm the deletion of your alert.

<Message type="tip">
  You can also delete an alert from the **Settings** tab of the alert.
</Message>

## Configure email address to receive notifications

The Alerting Management feature is linked to the notification manager. The email address set in the notification manager is where you will receive notifications when alerts are triggered.

For details on how to configure email addresses and notifications, see the related [notification manager documentation](/account/profile-preferences/manage-notifications/). 

<Message type="important">
  Because Audit Trail alerts are classified as Security notifications, ensure you set the email address(es) to subscribe to the Security notification type.
</Message>

Email notifications contain:
- details of the alert, such as:
  - name of the alert
  - time when the alert was triggered
  - behavior detected
  - severity
- recommended actions to help you with investigation and mitigation steps
- a link to check the Audit Trail page in the console with filters helping you to see what happened around the affected timeframe
