[Object Storage private access](/vpc/how-to/enable-object-storage-private-access/) relies on two independent components: the feature enabled on the VPC, which creates the private path, and a bucket policy with an `aws:SourceVpc` condition, which restricts access to the bucket. Most issues come from one of the two components being missing or incomplete.

## My bucket is still reachable from the internet

### Cause

Object Storage private access is enabled on the VPC, but no bucket policy restricts access to the bucket. Enabling the feature adds a private path, and does not remove public access.

Alternatively, a bucket policy that contained the VPC condition was deleted, which removes all restrictions on the bucket.

### Solution

Apply a bucket policy with an `aws:SourceVpc` condition on the bucket, as described in [How to restrict bucket access to a VPC](/vpc/how-to/enable-object-storage-private-access/#how-to-restrict-bucket-access-to-a-vpc).

## Resources in my VPC cannot reach my bucket

### Cause

The private path is incomplete, or the bucket policy never matches the requests coming from the VPC.

### Solution

Check the following points:

- Object Storage private access is enabled on the VPC.
- The Private Network of the resource is authorized on the VPC.
- The bucket is in the region of the VPC.
- The bucket policy references the ID of a VPC on which Object Storage private access is enabled. A condition that references any other VPC never matches a request.

## The Scaleway console no longer displays my objects, metrics, or logs

### Cause

The Scaleway console accesses buckets over the internet. When the bucket policy denies requests that do not come from the VPC, the console requests are denied.

### Solution

Manage the bucket from a resource inside the VPC. If you no longer need the restriction, delete or edit the bucket policy.

## I lost access to my bucket

### Cause

The bucket policy allows requests coming from the VPC only, and you have no management method from inside the VPC.

### Solution

The [Owner](/iam/concepts/#owner) of the Organization always has the right to put and delete bucket policies, even when the policy does not allow them to perform other bucket operations. Ask the Owner of the Organization to edit or delete the bucket policy.
