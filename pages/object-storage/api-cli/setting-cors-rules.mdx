[Cross-Origin Resource Sharing (CORS)](https://en.wikipedia.org/wiki/Cross-origin_resource_sharing) is a browser security mechanism that controls whether a web page served from one domain can request resources hosted on another. By default, browsers block such cross-origin requests. Because Object Storage buckets are served from a Scaleway domain, a web application hosted on your own domain cannot fetch or upload objects directly from the browser unless the bucket explicitly allows it.

You set CORS rules at the bucket level using a JSON file. They define which origins (domains) are allowed to access the bucket, which HTTP methods and headers they can use, and how long the browser can cache the permission. When a browser sends a cross-origin request to the bucket, Object Storage checks it against the configured rules and returns the appropriate headers. The browser then enforces the response, allowing or blocking the request accordingly.

- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/#owner) status or [IAM permissions](/iam/concepts/#permission) allowing you to perform actions in the intended Organization

## Set CORS on an Object Storage bucket

1. Create a new file called `cors.json` locally.
2. Open the file and add the following content. Replace the placeholders with the appropriate domains (origins) or an asterisk (`*`) to allow any domain, and adjust the parameters as needed.

    ```json
    {
      "CORSRules": [
        {
          "AllowedOrigins": ["https://DOMAIN_NAME", "https://www.DOMAIN_NAME"],
          "AllowedHeaders": ["*"],
          "AllowedMethods": ["GET", "HEAD", "POST", "PUT", "DELETE"],
          "MaxAgeSeconds": 3000,
          "ExposeHeaders": ["Etag"]
        }
      ]
    }
    ```

3. Run the command below to apply the CORS configuration to the bucket with the AWS CLI. Replace `BUCKET_NAME` with the name of the bucket.
    ```sh
    aws s3api put-bucket-cors --bucket BUCKET_NAME --cors-configuration file://cors.json
    ```

    The command returns no output.

## Get the CORS configuration of a bucket

Run the command below to display the CORS configuration of a bucket:

```sh
aws s3api get-bucket-cors --bucket BUCKET_NAME
```

If CORS rules are set for the bucket, the API returns a JSON list like this example:
```json
{
  "CORSRules": [
      {
          "AllowedHeaders": [
              "*"
          ],
          "AllowedMethods": [
              "GET",
              "HEAD",
              "POST",
              "PUT",
              "DELETE"
          ],
          "AllowedOrigins": [
              "https://DOMAIN_NAME",
              "https://www.DOMAIN_NAME"
          ],
          "ExposeHeaders": [
              "Etag"
          ],
          "MaxAgeSeconds": 3000
      }
  ]
}
```

If no CORS rules are set for the bucket, the request returns the following error:

```
An error occurred (NoSuchCORSConfiguration) when calling the GetBucketCors operation: The CORS configuration does not exist
```

## Test the CORS configuration of a bucket

To test the CORS rules of a bucket, use `curl` with the desired methods (`GET`, `POST`, etc.), as shown below. Replace the placeholders with appropriate values.

```sh
curl -i -X OPTIONS -H 'Origin: https://DOMAIN_NAME' https://BUCKET_NAME.s3.S3_REGION.scw.cloud/OBJECT_KEY -H "Access-Control-Request-Method: GET"
```

If the origin and method are allowed, the request returns a `200` response with the `Access-Control-*` headers derived from your configuration:

```
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://DOMAIN_NAME
Access-Control-Allow-Methods: GET, HEAD, POST, PUT, DELETE
Access-Control-Allow-Headers: *
Access-Control-Expose-Headers: Etag
Access-Control-Max-Age: 3000
```

If the origin or method is not allowed, or if no CORS configuration is set on the bucket, the request returns a `403` response with an `AccessForbidden` error and no `Access-Control-*` headers.

## Delete the CORS configuration of a bucket

Run the command below to delete the CORS rules of a bucket:

```sh
aws s3api delete-bucket-cors --bucket BUCKET_NAME
```

If the operation is successful, the command returns no output. You can [retrieve the CORS configuration](#get-the-cors-configuration-of-a-bucket) of the bucket to make sure it was properly deleted.

## Troubleshooting

If you encounter errors while using CORS rules with Scaleway Object Storage, make sure that:

- you have configured the [AWS CLI](/object-storage/api-cli/object-storage-aws-cli/) using your Scaleway credentials.
- you have the `ObjectStorageBucketsWrite` or `ObjectStorageFullAccess` [IAM permissions](/iam/how-to/view-permission-sets/).

See the [dedicated troubleshooting pages](/object-storage/troubleshooting/) to get more help with Scaleway Object Storage.
