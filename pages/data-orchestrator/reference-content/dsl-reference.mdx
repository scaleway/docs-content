This page explains the concepts supported by the Data Orchestrator DSL with detailed definitions and property tables.
Data Orchestrator is vendor-neutral and open-source as it is based on the [Open Workflow DSL Reference](https://github.com/open-workflow-specification/specification/blob/main/dsl-reference.md).

Some concepts are exclusive to Data Orchestrator and are marked as such in the reference. Concepts that are not yet implemented in the current version are listed in the [Concepts not implemented in Data Orchestrator](#concepts-not-implemented-in-data-orchestrator) section.

## Workflow

A workflow is a blueprint outlining the series of [tasks](#task) required to execute a specific business operation. It details the sequence in which [tasks](#task) must be completed, guiding users through the process from start to finish, and helps streamline operations, ensure consistency, and optimize efficiency within an organization.

**Properties**

| Property&nbsp;name |              Type               | Required |                                                                                      Description                                                                                      |
| :----------------- | :------------------------------ | :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `document`         | [document](#document)           | yes      | Documents the defined workflow.                                                                                                                                                       |
| `input`            | [input](#input)                 | no       | Configures the input of the workflow.                                                                                                                                                 |
| `use`              | [use](#use)                     | no       | Defines the [reusable components](#use) of the workflow, if any.                                                                                                                      |
| `do`               | map[string,&nbsp;[task](#task)] | yes      | The [task(s)](#task) that must be performed by the workflow.                                                                                                                          |
| `timeout`          | string<br />[timeout](#timeout) | no       | The configuration, if any, of the timeout of the workflow.<br /> If a `string`, must be the name of a [timeout](#timeout) defined in the [reusable components](#use) of the workflow. |
| `output`           | [output](#output)               | no       | Configures the output of the workflow.                                                                                                                                                |
| `evaluate`         | [evaluate](#evaluate)           | no       | Configures runtime expression evaluation.                                                                                                                                             |

### Document

Documents the workflow definition.

| Property&nbsp;name |        Type         | Required |                         Description                          |
| :----------------- | :------------------ | :------- | :----------------------------------------------------------- |
| `dsl`              | string              | yes      | The version of the DSL used to define the workflow.          |
| `namespace`        | string              | yes      | The namespace of the workflow.                               |
| `name`             | string              | yes      | The name of the workflow.                                    |
| `version`          | string              | yes      | The [semantic version](https://semver.org/) of the workflow. |
| `title`            | string              | no       | The title of the workflow.                                   |
| `summary`          | string              | no       | The Markdown summary of the workflow.                        |
| `tags`             | map[string, string] | no       | A key/value mapping of the tags of the workflow, if any.     |
| `metadata`         | map                 | no       | Additional information about the workflow.                   |

### Use

Defines the reusable components of the workflow.

| Property&nbsp;name |                      Type                      | Required |                          Description                          |
| :----------------- | :--------------------------------------------- | :------- | :------------------------------------------------------------ |
| `authentications`  | map[string, [authentication](#authentication)] | no       | A name/value mapping of the reusable authentication policies. |
| `errors`           | map[string, [error](#error)]                   | no       | A name/value mapping of the reusable errors.                  |
| `functions`        | map[string, [task](#task)]                     | no       | A name/value mapping of the reusable tasks.                   |
| `retries`          | map[string, [retryPolicy](#retry)]             | no       | A name/value mapping of the reusable retry policies.          |
| `secrets`          | string[]                                       | no       | A list containing the secrets of the workflow.                |
| `timeouts`         | map[string, [timeout](#timeout)]               | no       | A name/value mapping of the reusable timeouts.                |

### Evaluate

Configures a runtime expression evaluation for the workflow.

| Property&nbsp;name |  Type  | Required |                                                                                                                                                                   Description                                                                                                                                                                    |
| :----------------- | :----- | :------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `language`         | string | no       | The language used for writing runtime expressions.<br />Defaults to `jq`.                                                                                                                                                                                                                                                                        |
| `mode`             | string | no       | The runtime expression evaluation mode.<br />Supported values are:<br />- `strict`: requires all expressions to be enclosed within `${ }` for proper identification and evaluation.<br />- `loose`: evaluates any value provided. If the evaluation fails, it results in a string with the expression as its content.<br />Defaults to `strict`. |

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: order-pet
  version: '0.1.0'
  title: Order Pet - 1.0.0
  summary: >
    # Order Pet - 1.0.0
    ## Table of Contents
    - [Description](#description)
    - [Requirements](#requirements)
    ## Description
    A sample workflow used to process an hypothetic pet order using the [PetStore API](https://petstore.swagger.io/)
    ## Requirements
    ## Secrets
    - my-oauth2-secret
use:
  authentications:
    petStoreOAuth2:
      oauth2: 
        authority: https://petstore.swagger.io/.well-known/openid-configuration
        grant: client_credentials
        client:
          id: workflow-runtime
          secret: "**********"
        scopes: [ api ]
        audiences: [ runtime ]
  extensions:
    - externalLogging:
        extend: all
        before:
          - sendLog:
              call: http
              with:
                method: post
                endpoint: https://fake.log.collector.com
                body:
                  message: ${ "Executing task '\($task.reference)'..." }
        after:
          - sendLog:
              call: http
              with:
                method: post
                endpoint: https://fake.log.collector.com
                body:
                  message: ${ "Executed task '\($task.reference)'..." }
  functions:
    getAvailablePets:
      call: openapi
      with:
        document:
          endpoint: https://petstore.swagger.io/v2/swagger.json
        operationId: findByStatus
        parameters:
          status: available
  secrets:
    - my-oauth2-secret
do:
  - getAvailablePets:
      call: getAvailablePets
      output:
        as: "$input + { availablePets: [.[] | select(.category.name == \"dog\" and (.tags[] | .breed == $input.order.breed))] }"
  - submitMatchesByMail:
      call: http
      with:
        method: post
        endpoint:
          uri: https://fake.smtp.service.com/email/send
          authentication: 
            use: petStoreOAuth2
        body:
          from: noreply@fake.petstore.com
          to: ${ .order.client.email }
          subject: Candidates for Adoption
          body: >
            Hello ${ .order.client.preferredDisplayName }!

            Following your interest to adopt a dog, here is a list of candidates that you might be interested in:

            ${ .pets | map("-\(.name)") | join("\n") }

            Please do not hesitate to contact us at info@fake.petstore.com if your have questions.

            Hope to hear from you soon!

            ----------------------------------------------------------------------------------------------
            DO NOT REPLY
            ----------------------------------------------------------------------------------------------
```

## Task

A task within a [workflow](#workflow) represents a discrete unit of work that contributes to achieving the overall objectives defined by the [workflow](#workflow). 

It encapsulates a specific action or set of actions that need to be executed in a predefined order to advance the workflow towards its completion. 

[Tasks](#task) are designed to be modular and focused, each serving a distinct purpose within the broader context of the [workflow](#workflow). 

By breaking down the [workflow](#workflow) into manageable [tasks](#task), organizations can effectively coordinate and track progress, enabling efficient collaboration and ensuring that work is completed in a structured and organized manner.

The Open Workflow DSL defines a list of [tasks](#task) that must be supported by all runtimes:

- [Call](#call), used to call services and/or functions.
- [Do](#do), used to define one or more subtasks to perform in sequence.
- [For](#for), used to iterate over a collection of items, executing one or more subtasks for each of them.
- [Fork](#fork), used to define one or more subtasks to perform concurrently.
- [Raise](#raise), used to raise an [error](#error) and potentially fault the [workflow](#workflow).
- [Run](#run), used to run a [Serverless container](#serverless-container-run-exclusive-to-data-orchestrator).
- [Switch](#switch), used to dynamically select and execute one of multiple alternative paths based on specified conditions
- [Set](#set), used to dynamically set the data of the workflow during its execution. 
- [Try](#try), used to attempt executing a specified [task](#task), and to handle any resulting [errors](#error) gracefully, allowing the [workflow](#workflow) to continue without interruption.
- [Wait](#wait), used to pause or wait for a specified duration before proceeding to the next task.

**Properties**

| Property&nbsp;name |               Type               | Required |                                                                                                                                                                                       Description                                                                                                                                                                                       |
| :----------------- | :------------------------------- | :------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `if`               | string                           | no       | A [runtime expression](https://github.com/open-workflow-specification/specification/blob/main/dsl.md#runtime-expressions) used to determine whether the task should be run, if any.<br />The task is considered skipped if not run, and the *raw* task input becomes the task output. The expression is evaluated against the *raw* task input before any other expression of the task. |
| `input`            | [input](#input)                  | no       | An object used to customize the task input and to document its schema, if any.                                                                                                                                                                                                                                                                                                          |
| `output`           | [output](#output)                | no       | An object used to customize the task output and to document its schema, if any.                                                                                                                                                                                                                                                                                                         |
| `export`           | [export](#export)                | no       | An object used to customize the content of the workflow context.                                                                                                                                                                                                                                                                                                                        |
| `timeout`          | string<br />[timeout](#timeout)  | no       | The configuration of the task timeout, if any.<br />If a `string`, must be the name of a [timeout](#timeout) defined in the [reusable components](#use) of the workflow.                                                                                                                                                                                                                |
| `then`             | [flowDirective](#flow-directive) | no       | The flow directive to execute next.<br />If not set, defaults to `continue`.                                                                                                                                                                                                                                                                                                            |
| `metadata`         | map                              | no       | Additional information about the task.                                                                                                                                                                                                                                                                                                                                                  |

### Call

The Call task enables the execution of a specified function within a workflow, allowing seamless integration with custom business logic or external services.

**Properties**

| Property&nbsp;name |  Type  | Required |                            Description                            |
| :----------------- | :----- | :------- | :---------------------------------------------------------------- |
| `call`             | string | yes      | The name of the function to call.                                 |
| `with`             | map    | no       | A name/value mapping of the parameters to call the function with. |

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: call-example
  version: '0.1.0'
do:
  - getPet:
      call: http
      with:
        method: get
        endpoint: https://petstore.swagger.io/v2/pet/{petId}
```

Open Workflow Specification defines several default functions that must be supported by all implementations and runtimes:

- [HTTP](#http-call)
- [Serverless-Job](#serverless-job-call-exclusive-to-data-orchestrator)
- [Serverless-Function](#serverless-function-call-exclusive-to-data-orchestrator)
- [Serverless-Container](#serverless-container-call-exclusive-to-data-orchestrator)
- [Object-Storage](#object-storage-call-exclusive-to-data-orchestrator)
- [Generative-API](#generative-api-call-exclusive-to-data-orchestrator)

#### HTTP Call

The [HTTP Call](#http-call) lets you call any external service over HTTP.

**Properties**

| Property&nbsp;name |             Type              | Required |                                                                                                                                                                       Description                                                                                                                                                                       |
| :----------------- | :---------------------------- | :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `method`           | string                        | yes      | The HTTP request method.                                                                                                                                                                                                                                                                                                                                |
| `endpoint`         | string\|[endpoint](#endpoint) | yes      | An URI or object that describes the HTTP endpoint to call.                                                                                                                                                                                                                                                                                              |
| `headers`          | map                           | no       | A name/value mapping of the HTTP headers to use, if any.                                                                                                                                                                                                                                                                                                |
| `body`             | any                           | no       | The HTTP request body, if any.                                                                                                                                                                                                                                                                                                                          |
| `query`            | map[string, any]              | no       | A name/value mapping of the query parameters to use, if any.                                                                                                                                                                                                                                                                                            |
| `output`           | string                        | no       | The output format of the HTTP call.<br />Supported values are:<br />- `content`: output the content of the [HTTP response](#http-response), possibly deserialized.<br />- `raw`: output the base-64 encoded [HTTP response](#http-response) content, if any.<br />- `response`: output the [HTTP response](#http-response).<br />Defaults to `content`. |
| `redirect`         | boolean                       | no       | Specifies whether to include or exclude status codes `300–399` from the error range.<br /> - If set to `true`, runtimes raise an error for status codes outside the `200–399` range.<br /> - If set to `false`, runtimes raise an error for response status codes outside the `200–299` range.<br />Defaults to `false`.                                |  
| `toObjectStorage`  | [ObjectStorageUpload](#object-storage-upload)    | no       | Streams the HTTP response body directly to Scaleway Object Storage via multipart upload, instead of returning it inline.<br />Use this for any response that may exceed the workflow payload limit (900 KB). The maximum upload size is 5 GB per file. When set, the task output is replaced by a small reference map (`bucket`, `key`, `region`, `size`, `etag`, `contentType`, `metadata`).<br />Defined at the task level, alongside `with`, and not inside the `with` mapping. See [Object Storage Upload](#object-storage-upload). |

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: http-example
  version: '0.1.0'
do:
  - getPet:
      call: http
      with:
        method: get
        endpoint: https://petstore.swagger.io/v2/pet/{petId}
```

*Example of an HTTP download streamed to Object Storage (`toObjectStorage`):*

```yaml
document:
  dsl: '1.0.3'
  namespace: examples
  name: call-http-to-object-storage
  version: '1.0.0'
do:
  - downloadLargeFile:
      call: http
      with:
        method: GET
        endpoint: https://example.com/large-file.jpeg
      toObjectStorage:
        scaleway:
          region: fr-par
        bucket: my-downloads
        key: images/large-file.jpeg
```

#### Serverless-Job Call (exclusive to Data Orchestrator)

The Scaleway Serverless Job Call lets you run recurring and autonomous tasks in the cloud.

**Properties**

| Property&nbsp;name |   Type   | Required |                                           Description                                            |
| :----------------- | :------- | :------- | :----------------------------------------------------------------------------------------------- |
| `id`               | string   | yes      | The ID of the Scaleway serverless job.                                                           |
| `region`           | string   | yes      | The region of the Scaleway serverless job.<br /> Supported values: `fr-par`, `nl-ams`, `pl-waw`. |
| `startupCommand`   | string[] | no       | The command to execute on the Scaleway Serverless Job.                                           |
| `args`             | string[] | no       | Arguments to pass to the command.                                                                |

<Message type="important">
  The workflow and the Serverless Job must be in the same project.
</Message>

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: mcp-example
  version: '0.1.0'
do:
  - pushDataOnS3:
      call: "serverless_job"
      with:
        id: "0dbc8c9f-e6f2-4dd5-88e0-a4b7a4743f02"
        region: "fr-par"
        startupCommand:
          - "sh"
          - "-c"
        args:
          - "echo 'print from workflow args'"
```

#### Serverless-Function Call (exclusive to Data Orchestrator)

The Scaleway Serverless Function Call lets you call the default endpoint of a Serverless Function.

Instead of using an HTTP endpoint (with potential authentication), you provide the function identifier (`id`) and the region (`region`) to invoke the function. The call handles authentication automatically.

| `id`               | string                | yes      | The ID of the Serverless Function.                                                                                                                                                                                                                                                                                                                      |
| `region`           | string                | yes      | The region where the Serverless Function is deployed.<br />Supported values: `fr-par`, `nl-ams`, `pl-waw`.                                                                                                                                                                                                                                                                                                   |
| `method`           | string                | yes      | The HTTP request method.                                                                                                                                                                                                                                                                                                                                |
| `headers`          | map                   | no       | A name/value mapping of the HTTP headers to use, if any.                                                                                                                                                                                                                                                                                                |
| `body`             | any                   | no       | The HTTP request body, if any.                                                                                                                                                                                                                                                                                                                          |
| `query`            | map[string,&nbsp;any] | no       | A name/value mapping of the query parameters to use, if any.                                                                                                                                                                                                                                                                                            |
| `output`           | string                | no       | The output format of the HTTP call.<br />Supported values are:<br />- `content`: output the content of the [HTTP response](#http-response), possibly deserialized.<br />- `raw`: output the base-64 encoded [HTTP response](#http-response) content, if any.<br />- `response`: output the [HTTP response](#http-response).<br />Defaults to `content`. |
| `toObjectStorage`  | [ObjectStorageUpload](#object-storage-upload) | no       | Streams the HTTP response body directly to Scaleway Object Storage via multipart upload, instead of returning it inline.<br />Use this for any response that may exceed the workflow payload limit (900 KB). The maximum upload size is 5 GB per file. When set, the task output is replaced by a small reference map (`bucket`, `key`, `region`, `size`, `etag`, `contentType`, `metadata`).<br />Defined at the task level, alongside `with`, and not inside the `with` mapping. See [Object Storage Upload](#object-storage-upload). |

<Message type="important">
  The workflow and the Serverless Function must be in the same project.
</Message>

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: function-example
  version: '0.1.0'

      call: "serverless_function"
      with:
        method: GET
        id: "c351de27-d595-44eb-8e4c-2f3d660baff8"
        region: "fr-par"
        output: "response"
```

#### Serverless-Container Call (exclusive to Data Orchestrator)

Instead of using an HTTP endpoint (with potential authentication), you provide the container identifier (`containerId`) - or the container name (`name`) together with the namespace identifier (`namespaceName` or `namespaceId`) - and region (`region`) to invoke the container. The call handles authentication automatically.

**Properties**

| Property&nbsp;name |         Type          | Required |                                                                                                                                                                       Description                                                                                                                                                                       |     |
| :----------------- | :-------------------- | :------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- |
| `containerId`      | string                | no       | The ID of the Serverless Container.<br />Required if `name` is not set.                                                                                                                                                                                                                                                                                 |     |
| `name`             | string                | no       | The name of the Serverless Container.<br />Required if `containerId` is not set.                                                                                                                                                                                                                                                                        |     |
| `namespaceId`      | string                | no       | The ID of the Serverless Container namespace.<br />Required if both `containerId` and `namespaceName` are not set.                                                                                                                                                                                                                                      |     |
| `namespaceName`    | string                | no       | The name of the Serverless Container namespace.<br />Required if both `containerId` and `namespaceId` are not set.                                                                                                                                                                                                                                      |     |
| `region`           | string                | yes      | The Scaleway region where the container is deployed.<br />Supported values: `fr-par`, `nl-ams`, `pl-waw`, `it-mil`.                                                                                                                                                                                                                                             |     |
| `method`           | string                | yes      | The HTTP request method.                                                                                                                                                                                                                                                                                                                                |     |
| `headers`          | map                   | no       | A name/value mapping of the HTTP headers to use, if any.                                                                                                                                                                                                                                                                                                |     |
| `body`             | any                   | no       | The HTTP request body, if any.                                                                                                                                                                                                                                                                                                                          |     |
| `query`            | map[string,&nbsp;any] | no       | A name/value mapping of the query parameters to use, if any.                                                                                                                                                                                                                                                                                            |     |
| `output`           | string                | no       | The output format of the HTTP call.<br />Supported values are:<br />- `content`: output the content of the [HTTP response](#http-response), possibly deserialized.<br />- `raw`: output the base-64 encoded [HTTP response](#http-response) content, if any.<br />- `response`: output the [HTTP response](#http-response).<br />Defaults to `content`. |     |
| `toObjectStorage`  | [ObjectStorageUpload](#object-storage-upload) | no       | Streams the HTTP response body directly to Scaleway Object Storage via multipart upload, instead of returning it inline.<br />Use this for any response that may exceed the workflow payload limit (900 KB). The maximum upload size is 5 GB per file. When set, the task output is replaced by a small reference map (`bucket`, `key`, `region`, `size`, `etag`, `contentType`, `metadata`).<br />Defined at the task level, alongside `with`, and not inside the `with` mapping.   The workflow and the Serverless Container must be in the same project.
</Message>

**Examples**

```yaml

  name: call-container-example

        method: GET

        region: "fr-par"
        output: "response"
```

#### Object Storage Call (exclusive to Data Orchestrator)

The Scaleway Object Storage Call lets you read from, write to, list, and delete objects in Scaleway Object Storage buckets directly from a workflow.

**Properties**

| Property&nbsp;name |                        Type                         | Required |                        Description                        |
| :----------------- | :--------------------------------------------------- | :------- | :-------------------------------------------------------- |
| `scaleway`         | [ObjectStorageScalewayArguments](#object-storage-scaleway-arguments) | yes      | Use Scaleway Object Storage.                              |
| `getObject`        | [ObjectStorageGetObjectArguments](#object-storage-get-object-arguments) | no       | Get an object from Object Storage.                        |
| `putObject`        | [ObjectStoragePutObjectArguments](#object-storage-put-object-arguments) | no       | Put an object to Object Storage.                          |
| `listObjectV2`     | [ObjectStorageListObjectV2Arguments](#object-storage-list-objects-arguments) | no       | List objects from Object Storage.                        |
| `deleteObject`     | [ObjectStorageDeleteObjectArguments](#object-storage-delete-object-arguments) | no       | Delete an object from Object Storage.                     |

#### Object Storage Scaleway Arguments

**Properties**

| Property&nbsp;name |  Type  | Required |                                                                                         Description                                                                                          |
| :----------------- | :----- | :------- | :---------------------------------------------------------------------------------------------------------------------------- |
| `region`           | string | yes      | The Scaleway region where the bucket is deployed.<br />Supported values: `fr-par`, `nl-ams`, `pl-waw`, `it-mil`.              |

#### Object Storage Get Object Arguments

**Properties**

| Property&nbsp;name |  Type  | Required |                                                                                                                                                 Description                                                                                                                                                 |
| :----------------- | :----- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bucket`           | string | yes      | The name of the Scaleway Object Storage bucket to read from.                                                                                                                                                                                 |
| `key`              | string | yes      | The key (path) of the object to get.                                                                                                                                                                                                          |
| `output`           | string | no       | The output format of the Object Storage call.<br />Supported values are:<br />- `content`: output the content of the response, possibly deserialized.<br />- `raw`: output the base-64 encoded response content, if any.<br />- `response`: output the response.<br />Defaults to `content`. |

#### Object Storage Put Object Arguments

**Properties**

| Property&nbsp;name |  Type  | Required |                                              Description                                               |
| :----------------- | :----- | :------- | :-------------------------------------------------------------------------------------------------------- |
| `bucket`           | string | yes      | The name of the Scaleway Object Storage bucket to write to.                                               |
| `key`              | string | yes      | The key (path) of the object to write.                                                                    |
| `input`            | string | no       | A runtime expression, if any, used to select the data to write.                                           |
| `contentType`      | string | no       | The content type of the file to write.                                                                    |
| `metadata`         | map    | no       | A name/value mapping of the metadata to attach to the object.                                            |

#### Object Storage List Objects Arguments

**Properties**

| Property&nbsp;name |  Type   | Required |                                                        Description                                                        |
| :----------------- | :------ | :------- | :---------------------------------------------------------------------------------------------------------------------- |
| `bucket`           | string  | yes      | The name of the Scaleway Object Storage bucket to list objects from.                                                    |
| `prefix`           | string  | no       | Limits the response to keys that begin with the specified prefix.                                                        |
| `delimiter`        | string  | no       | A character used to group keys, such as `/`. Matching key prefixes are rolled up into the response.                     |
| `maxKeys`          | integer | no       | The maximum number of keys returned in the response.<br />Defaults to `1000`.                                            |
| `fetchOwner`       | boolean | no       | Specifies whether to return the owner of each object in the response.<br />Defaults to `false`.                          |

#### Object Storage Delete Object Arguments

**Properties**

| Property&nbsp;name |  Type  | Required |                                                                                         Description                                                                                          |
| :----------------- | :----- | :------- | :---------------------------------------------------------------------------------------------------------------------------- |
| `bucket`           | string | yes      | The name of the Scaleway Object Storage bucket to delete from.                                                                 |
| `key`              | string | yes      | The key (path) of the object to delete.                                                                                       |
| `ifMatch`          | string | no       | Deletes the object only if its ETag matches the specified value.<br />If the ETags do not match, the operation fails with a `412 Precondition Failed` error.<br />Set to `*` to match any ETag. |

<Message type="important">
  The workflow and the bucket must be in the same project.
</Message>

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: examples
  name: object-storage-example
  version: '1.0.0'
do:
  - callGetStarWars:
      call: "object_storage"
      with:
        scaleway:
          region: fr-par
        getObject:
          bucket: coruscant
          key: "starwars/characters.json"
          output: 'content' # raw, content, response
  - callPutStarWars:
      call: "object_storage"
      with:
        scaleway:
          region: fr-par
        putObject:
          bucket: alderaan
          key: "starwars/characters-names.txt"
          contentType: text/plain
          input: ${ [.[].name] | join(", ") }
          metadata:
            sample: value
  - callListStarWars:
      call: "object_storage"
      with:
        scaleway:
          region: fr-par
```

#### Generative API Call (exclusive to Data Orchestrator)

The Scaleway Generative API Call lets you call [Scaleway Generative APIs](https://www.scaleway.com/en/developers/api/generative-apis) directly from a workflow.

It supports five endpoint families, selectable via the `with` arguments:
- **Chat completions** (`chat`) - `POST /v1/chat/completions`
- **Responses** (`responses`) - `POST /v1/responses`
- **Embeddings** (`embeddings`) - `POST /v1/embeddings`
- **Rerank** (`rerank`) - `POST /v1/rerank`
- **Audio transcription** (`transcription`) - `POST /v1/audio/transcriptions`

The model is selected through either a **Serverless** or a **Dedicated** deployment. The task handles authentication, project routing, and response deserialization for you.

**Properties**

| Property&nbsp;name |                        Type                        | Required |                                                                                                                                                        Description                                                                                                                                                         |
| :----------------- | :--------------------------------------------------- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `serverless`       | [GenerativeApiServerless](#generative-api-serverless)   | no       | The Scaleway Serverless model configuration.<br />Exactly one of `serverless` or `dedicated` must be set.                                                                                                                                                                                                                   |
| `dedicated`        | [GenerativeApiDedicated](#generative-api-dedicated)     | no       | The Scaleway Dedicated model configuration.<br />Exactly one of `serverless` or `dedicated` must be set.                                                                                                                                                                                                                     |
| `chat`             | [ChatArguments](#chat-arguments)                        | no       | The chat completions arguments.<br />Exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set.                                                                                                                                                                                             |
| `responses`        | [ResponsesArguments](#responses-arguments)             | no       | The responses arguments.<br />Exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set.                                                                                                                                                                                                     |
| `embeddings`       | [EmbeddingsArguments](#embeddings-arguments)           | no       | The embeddings arguments.<br />Exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set.                                                                                                                                                                                                    |
| `rerank`           | [RerankArguments](#rerank-arguments)                   | no       | The rerank arguments.<br />Exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set.                                                                                                                                                                                                       |
| `transcription`    | [TranscriptionArguments](#transcription-arguments)     | no       | The audio transcription arguments.<br />Exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set.                                                                                                                                                                                           |
| `headers`          | map[string, string]                                     | no       | A name/value mapping of the HTTP headers, if any, of the Generative API request to perform.                                                                                                                                                                                                                                 |
| `output`           | string                                                  | no       | The output format of the Generative API call.<br />Supported values are:<br />- `content`: output the content of the [HTTP response](#http-response), possibly deserialized.<br />- `raw`: output the base-64 encoded [HTTP response](#http-response) content, if any.<br />- `response`: output the [HTTP response](#http-response).<br />Defaults to `content`. |
| `toObjectStorage`  | [ObjectStorageUpload](#object-storage-upload)           | no       | Streams the Generative API response body directly to Scaleway Object Storage via multipart upload, instead of returning it inline.<br />Use this for any response that may exceed the workflow payload limit (900 KB), such as long transcriptions or chat completions. The maximum upload size is 5 GB per file. When set, the task output is replaced by a small reference map (`bucket`, `key`, `region`, `size`, `etag`, `contentType`, `metadata`).<br />Defined at the task level, alongside `with`, and not inside the `with` mapping. See [Object Storage Upload](#object-storage-upload). |

<Message type="important">
  Exactly one of `serverless` or `dedicated` must be set, and exactly one of `chat`, `responses`, `embeddings`, `rerank`, or `transcription` must be set. Streaming is not supported: the `stream` field must be `false` or unset for `chat` and `responses`.
</Message>

<Message type="important">
  The workflow and the Generative API resource must be in the same project.
</Message>

**Examples**

**Basic chat completion with a Serverless model:**

```yaml
document:
  dsl: '1.0.3'
  namespace: examples
  name: call-generative-api
  version: '1.0.0'
do:
  - askModel:
      call: "generative_api"
      with:
        serverless:
          model: "llama-3.3-70b-instruct"
        output: "content"
        chat:
          messages:
            - role: "system"
              content: "You are a helpful assistant."
            - role: "user"
              content: "${ .user_prompt }"
          temperature: 0.7
          maxTokens: 100
          topP: 0.9
```

### For

The For task lets you iterate over a collection of items, executing one or more subtasks for each of them. The output of each iteration is passed as the input of the next one.

**Properties**

| Property&nbsp;name |             Type             | Required |                                                                        Description                                                                        |
| :----------------- | :--------------------------- | :------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `for`              | [for configuration](#for-configuration) | yes      | The configuration of the loop.                                                                                                                             |
| `while`            | string                       | no       | A runtime expression evaluated after each iteration on the accumulated output.<br />The loop stops as soon as the expression evaluates to `false`.          |
| `do`               | map[string, [task](#task)]   | yes      | The tasks to perform for each item of the collection, sequentially.                                                                                        |

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: for-example
  version: '0.1.0'
do:
  - prepareColors:
      set:
        colors:
          - red
          - green
          - blue
  - logColors:
      for:
        each: color
        in: ${ .colors }
        at: index
      do:
        - logColor:
            set:
              currentColor: ${ $color }
              currentIndex: ${ $index }
```

#### For Configuration

The configuration of the loop of a [For](#for) task.

| Property&nbsp;name |  Type  | Required |                                                                                 Description                                                                                  |
| :----------------- | :----- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `each`             | string | no       | The name of the variable holding the current item.<br />Defaults to `item`, exposed as the `$item` runtime expression variable.                                                |
| `in`               | string | yes      | A runtime expression that evaluates to the collection to iterate over.                                                                                                         |
| `at`               | string | no       | The name of the variable holding the index of the current item.<br />Defaults to `index`, exposed as the `$index` runtime expression variable.                                |

<Message type="note">
  If the `in` expression evaluates to a single value instead of a collection, the `do` subtasks are executed once with that value. If it evaluates to `null`, they are not executed at all.
</Message>

The Try-catch task lets you handle known error types, such as authentication, authorization, and timeout. You can retry a failed task a set number of times before falling back to an alternative task if it keeps failing.

## Flow Directive

Flow Directives are commands within a workflow that dictate its progression.

| Flow&nbsp;directive |                                                                               Description                                                                               |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `continue`          | Instructs the workflow to proceed with the next task in line. This may conclude the execution of a workflow or branch if there is no task defined after the `continue`. |
| `end`               | Concludes the workflow execution and signal its completion with a `succeeded` status.                                                                                   |
| `exit`              | Completes the current parent `do` execution. This may conclude the execution of a workflow or branch if there is no task defined after the parent `do` scope.           |

## Runtime Expression Variables

Runtime expressions are evaluated in the language configured by the [evaluate](#evaluate) property of the workflow, which defaults to `jq`. In `strict` mode (default), expressions must be enclosed within `${ }`.

When evaluated, a runtime expression has access to the data it is evaluated against (using `.`), and to the following variables:

| Variable |  Type  |                                                                                                                                                   Description                                                                                                                                                   |
| :------- | :----- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.`      | any    | The root of the data the expression is evaluated against: the raw or transformed input/output, depending on where the expression is used.                                                                                                                                                                       |
| `$context` | map  | The workflow's context data, updated by the [export](#export) property of tasks. For example, `'$context+.'` merges the task output into the current context.                                                                                                                                               |
| `$input` | any    | The transformed input of the workflow or task (see [input](#input)).                                                                                                                                                                                                                                            |
| `$output` | any   | The transformed output of the task (see [output](#output)).                                                                                                                                                                                                                                                                                     |
| `$workflow` | object | The descriptor of the current workflow: its definition (e.g. `$workflow.definition.document.name`), its raw input (e.g. `$workflow.input.chat.roomId`), and its start time.                                                                                                                               |
| `$task` | object  | The descriptor of the current task: its name, reference (e.g. `$task.reference`), definition, raw input, raw output, and start time.                                                                                                                                                                            |
| `$secrets` | map   | A key/value mapping of the workflow's secrets, as defined in the [reusable components](#use) of the workflow. Use it with caution, as passing secrets as call inputs may inadvertently expose sensitive information.                                                                                        |
| `$runtime` | object | The descriptor of the runtime executing the workflow (name, version, and metadata).                                                                                                                                                                                                                             |

<Message type="note">
  The [catch](#catch) clause of a [try](#try) task also exposes the caught [error](#error) as a variable, named `error` by default (see the `as` property).
</Message>

**Examples**

```yaml
document:
  dsl: '1.0.3'
  namespace: test
  name: runtime-expression-variables-example
  version: '0.1.0'
do:
  - logInfo:
      if: ${ $input.order != null }
      set:
        message: ${ "Task '\($task.reference)' is processing order '\($input.order.id)' in workflow '\($workflow.definition.document.name)'." }
        contextTags: ${ $context.tags }
```

## URI Template

The DSL has limited support for URI template syntax as defined by [RFC 6570](https://datatracker.ietf.org/doc/html/rfc6570). Specifically, only the [Simple String Expansion](https://datatracker.ietf.org/doc/html/rfc6570#section-3.2.2) is supported, which allows authors to embed variables in a URI.

URI-typed string fields that use the schema `uriTemplate` type accept [URI-references](https://datatracker.ietf.org/doc/html/rfc3986#section-4.1) as defined by [RFC 3986](https://datatracker.ietf.org/doc/html/rfc3986), meaning both absolute URIs (e.g., `https://example.com/path`) and relative references (e.g., `openapi/petstore.json`, `/api/v1/users`) are accepted. In the JSON Schema, both `LiteralUri` and `LiteralUriTemplate` are validated using the RFC 3986 Appendix B URI-reference regex (with an extra guard to avoid matching runtime expressions).

To substitute a variable within a URI, use the `{}` syntax. The identifier inside the curly braces will be replaced with its value during runtime evaluation. If no value is found for the identifier, an empty string will be used.

This has the following limitations compared to runtime expressions:

- Only top-level properties can be interpolated within strings, thus identifiers are treated verbatim. This means that `{pet.id}` will be replaced with the value of the `"pet.id"` property, not the value of the `id` property of the `pet` property.
- The referenced variable must be of type `string`, `number`, `boolean`, or `null`. If the variable is of a different type an error with type `https://open-workflow-specification.org/spec/1.0.0/errors/expression` and status `400` will be raised.
- Runtime expression arguments are not available for string substitution.

**Examples**

```yaml
uri: https://petstore.swagger.io/v2/pet/{petId}
```

## Object Storage Source

References a Scaleway Object Storage object used as a content source for the [Generative API Call](#generative-api-call-exclusive-to-data-orchestrator). This implements the **claim-check pattern** for large inputs: the object is downloaded (or exposed via a presigned URL) at runtime, so its content never transits through the workflow runtime. Objects downloaded in-memory are bounded by a 25 MB limit; larger objects should use the presigned URL mode (image/video).

Used by:
- [AudioData.objectStorage](#audio-data) (transcription, chat `input_audio`) - downloaded in-memory by the runtime
- [FileData.objectStorage](#file-data) (chat `file`, OCR) - downloaded in-memory by the runtime
- [MediaSource.objectStorage](#media-source) (chat `image_url`, `video_url`) - exposed via a presigned GET URL; the Generative API fetches the media itself
- [ResponseAPIInputContentPart.objectStorage](#response-api-input-content-part) (responses `input_image`, `input_file`) - presigned or downloaded

Exactly one provider must be set (only `scaleway` is supported today). The provider mirrors the [Object Storage Call](#object-storage-call-exclusive-to-data-orchestrator) arguments.

**Properties**

| Property&nbsp;name |                        Type                         | Required |                        Description                        |
| :----------------- | :--------------------------------------------------- | :------- | :-------------------------------------------------------- |
| `scaleway`         | [ObjectStorageScalewayArguments](#object-storage-scaleway-arguments) | yes | Use Scaleway Object Storage.                              |
| `bucket`           | string                                               | yes      | The name of the Scaleway Object Storage bucket to read from. |
| `key`              | string                                               | yes      | The key (path) of the object to read.                      |

<Message type="note">
  When a presigned GET URL is used (for `image_url`, `video_url`, and responses `input_image`), a temporary IAM API key with limited permissions is created for each workflow run to generate the presigned URL. This key is visible in the [Scaleway console](https://console.scaleway.com/iam/api-keys) under IAM > API Keys, with an explicit description referencing the workflow, and is automatically marked as expired once the presigned URL expires.
</Message>

**Examples**

```yaml
objectStorage:
  scaleway:
    region: fr-par
  bucket: my-documents
  key: reports/2024-annual-report.pdf
```

## Object Storage Upload

Configures a `toObjectStorage` upload that persists a large task output to Scaleway Object Storage. This implements the **claim-check pattern** for large outputs: the response body is streamed directly to Object Storage via multipart upload and a small reference map is returned instead of the inline content, so it never hits the workflow payload size limit (900 KB). The maximum upload size is 5 GB per file.

Available on the [HTTP](#http-call), [Serverless-Function](#serverless-function-call-exclusive-to-data-orchestrator), [Serverless-Container](#serverless-container-call-exclusive-to-data-orchestrator), and [Generative-API](#generative-api-call-exclusive-to-data-orchestrator) call tasks, via the `toObjectStorage` property. Note that `toObjectStorage` is defined at the task level, alongside `with`, and not inside the `with` mapping.

When `jsonPath` is set, only the value at that path in the JSON response is uploaded (e.g. `text` for transcription, `choices[0].message.content` for chat). Extraction is streaming, so the rest of the body is never materialized in memory. When `jsonPath` is not set, the raw response body is uploaded as-is.

Supported `jsonPath` syntax: `text`, `a.b.c`, `arr[0]`, `[0].field`, `choices[0].message.content`. Not supported: wildcards (`*`), filters (`[?(...)]`), recursive descent (`..`).

For string targets, the unescaped content is written as-is. For non-string targets, the JSON representation is written as-is.

When `toObjectStorage` is set, the task output is replaced by a small reference map:

```json
{
  "bucket": "out-bucket",
  "key": "result.json",
  "region": "fr-par",
  "size": 5242880,
  "etag": "\"abc123\"",
  "contentType": "application/json",
  "metadata": {"author": "test"}
}
```

**Properties**

| Property&nbsp;name |                        Type                         | Required |                        Description                        |
| :----------------- | :--------------------------------------------------- | :------- | :-------------------------------------------------------- |
| `scaleway`         | [ObjectStorageScalewayArguments](#object-storage-scaleway-arguments) | yes | Use Scaleway Object Storage.                              |
| `bucket`           | string                                               | yes      | The name of the Scaleway Object Storage bucket to write to. |
| `key`              | string                                               | yes      | The key (path) of the object to write.                     |
| `metadata`         | map[string, string]                                  | no       | A key/value mapping of the metadata, if any, to attach to the uploaded object. |
| `contentType`      | string                                               | no       | The content type, if any, of the uploaded object.          |
| `jsonPath`         | string                                               | no       | A simplified JSONPath selector, if any, to extract and upload only a sub-path of the JSON response.<br />Supported syntax: `text`, `a.b.c`, `arr[0]`, `[0].field`, `choices[0].message.content`.<br />Not supported: wildcards (`*`), filters (`[?(...)]`), recursive descent (`..`). |

**Examples**

```yaml
toObjectStorage:
  scaleway:
    region: fr-par
  bucket: my-transcripts
  key: reports/2024-annual-report.txt
  jsonPath: choices[0].message.content
  contentType: "text/plain"
  metadata:
    source-model: "lightonocr-3-0.8b"
```

## Container Lifetime

Configures the lifetime of a container.

**Properties**

| Property&nbsp;name |         Type          | Required |                                                                                                                                                        Description                                                                                                                                                         |
| ------------------ | :-------------------- | :------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cleanup`          | string                | yes      | The cleanup policy to use.<br />Supported values are:<br />- `always`: the container is deleted immediately after execution.<br />-`never`: the runtime should never delete the container.<br />-`eventually`: the container is deleted after a configured amount of time after its execution.<br />Defaults to `never`. |
| `after`            | [duration](#duration) | no       | The [duration](#duration), if any, after which to delete the container once executed.<br />Required if `cleanup` has been set to `eventually`, otherwise ignored.                                                                                                                                                          |

## Process Result

Describes the result of a process.

**Properties**

| Property&nbsp;name |  Type   | Required |        Description         |
| :----------------- | :------ | :------- | :------------------------- |
| `code`             | integer | yes      | The process exit code.     |
| `stdout`           | string  | yes      | The process STDOUT output. |
| `stderr`           | string  | yes      | The process STDERR output. |

**Examples**

## Concepts not implemented in Data Orchestrator

The following concepts are not supported in the current version:

- Schedule
- Call:
  - Function
  - AsyncAPI
  - gRPC
  - OpenAPI
  - A2A
  - MCP
- Emit
- Listen
- Run (generic process types: `container`, `script`, `shell`, `workflow`)
- Lifecycle events
- External resources
- Authentication:
  - OAuth2
  - OpenIDConnect
- Catalog
- Extension
- Event Consumption Strategy
- Event Filter
- Event Properties
- AsyncAPI Outbound Message
- AsyncAPI Server
- AsyncAPI Subscription
- Workflow Definition Reference
- Subscription Iterator

<Message type="note">
  The only supported `run` process type is the Scaleway-specific `serverless_container`, described in [Serverless Container Run](#serverless-container-run-exclusive-to-data-orchestrator).
</Message>
