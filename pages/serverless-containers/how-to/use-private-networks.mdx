[Private Networks (PNs)](/serverless-containers/concepts/#private-networks) let your Serverless Containers communicate in an isolated and secure network without needing to be connected to the public internet. Each container can be connected to one Private Network. VPC Routing is supported and lets you build your own network topologies.

For full information about Scaleway Private Networks and VPC, see the [VPC documentation](/vpc/) and its [best practices guide](/vpc/reference-content/getting-most-private-networks/).

## Attach a Serverless Container to a Private Network

<Message type="tip">
  A container attached to a PN can communicate with other resources attached to PNs in the same VPC.
</Message>

<Tabs>
  <TabsTab label="Existing container">
  1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Serverless** > **Containers**. The containers page appears.
  2. Click the relevant containers namespace.
  3. Click the name of the container you want to manage.
  4. In the **Network & Domains** tab, click **Attach Private Network**, then select the VPC and PN from the dropdowns.
  5. (Optional) Check **Enable private endpoint** so other resources attached to PNs within the same VPC can use the container private endpoint to communicate with it.
  6. Click **Attach Private Network**.
  
  Your container is redeployed, and is now attached to the selected PN.
  If the private endpoint is enabled, you can copy its URL or download its certificate. See [Private endpoint HTTPS access and Certificate Authority (CA) trust](#private-endpoint-https-access-and-certificate-authority-ca-trust) for more information.
  
  <Message type="tip">
  You can disable the public endpoint for your container to prevent it from being accessed from the public internet. 
  Note that [triggers](/serverless-containers/how-to/add-trigger-to-a-container/) set for a Serverless Container work whether the public endpoint and private endpoint are enabled or not.
  </Message>

</TabsTab>
<TabsTab label="New container">
  1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Serverless** > **Containers**. The containers page appears.
  2. Click the **containers namespace** in which you want to create your container. If you have none, you can create one in the next step.
  3. Click **Deploy container**. The container creation wizard appears.
  4. In the **Configure network and endpoints** section:
      1. Check **Attach Private Network**.
      2. Select the VPC from the dropdown.
      3. Select the Private Network from the dropdown.
  5. (Optional) Check **Enable private endpoint** so other resources attached to PNs within the same VPC can use the container private endpoint to communicate with it.
  6. (Optional) Uncheck **Enable public endpoint** for your container to prevent it from being accessed from the public internet.
  7. Configure the other parameters of your container, then click **Deploy container**. See [Build and push a container image](/serverless-containers/how-to/build-push-container-image/) for more information.

  Your new container is deployed, and is attached to the selected PN.
  If the private endpoint is enabled, you can copy its URL or download its certificate. See [Private endpoint HTTPS access and Certificate Authority (CA) trust](#private-endpoint-https-access-and-certificate-authority-ca-trust) for more information.

  Note that [triggers](/serverless-containers/how-to/add-trigger-to-a-container/) set for a Serverless Container work whether the public endpoint and private endpoint are enabled or not.

### Enable a container private endpoint

When a container is attached to a PN, the other resources attached to the same PN can use the private endpoint to communicate with your container.

1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Serverless** > **Containers**. The containers page appears.
2. Click the relevant containers namespace.
3. Click the name of the container you want to manage.
4. In the **Network & Domains** tab, under **Private endpoint**, click **Enable private endpoint**.
5. In the confirmation dialog, click **Enable private endpoint**.

### Retrieve and use the private endpoint of a container

A container private endpoint uses the format `http://<CONTAINER_ID>.<PRIVATE_NETWORK_ID>.internal`. 
You can use this URL from a resource with connectivity to the corresponding VPC, for example:
```
  curl http://<CONTAINER_ID>.<PRIVATE_NETWORK_ID>.internal
```
The Serverless Containers API returns the private endpoint in the container `private_endpoint` field. If the private endpoint is not enabled, the field is not returned.

If authentication is enabled on the container, you must provide the required authentication when accessing it through either its public or private endpoint.
```
curl -H "X-Auth-Token: $SCW_SECRET_KEY" http://<CONTAINER_ID>.<PRIVATE_NETWORK_ID>.internal
```

### Private endpoint HTTPS access and Certificate Authority (CA) trust

Clients must trust the Scaleway containers private endpoint CA when establishing an HTTPS connection. To establish this connection, retrieve the CA and add it to the trust store of your client.

You can download the CA from the Scaleway console or retrieve it through the Serverless Containers API, CLI, Terraform provider, or SDK.

For example using the API, for the `fr-par` region:

1. Download the CA from: `https://api.scaleway.com/containers/v1/regions/fr-par/private-endpoint-ca?dl=1`
2. Save the certificate locally, for example, as `private-endpoint-ca.pem`. 
3. Provide the CA explicitly when accessing your container, for example:
    ```
    curl --cacert ./private-endpoint-ca.pem https://<CONTAINER_ID>.<PRIVATE_NETWORK_ID>.internal
    ```
    The `--cacert` option tells curl to trust the provided CA when verifying the TLS certificate presented by the private endpoint.

Alternatively, you can add the CA to the trust store of your application, container image, or operating system. You can then connect over HTTPS without having to provide the CA explicitly for every request.
```
  curl https://<CONTAINER_ID>.<PRIVATE_NETWORK_ID>.internal  
```

### Disable a container private endpoint

1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Serverless** > **Containers**. The containers page appears.
2. Click the relevant containers namespace.
3. Click the name of the container you want to manage.
4. In the **Network & Domains** tab, under **Private endpoint**, click **Disable private endpoint**.
5. In the confirmation dialog, click **Disable private endpoint**.

## Detach a container from a Private Network

<Message type="warning">
  Detaching a container from a PN disables its private endpoint and may end connectivity with other resources attached to the same PN.
</Message>

1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Serverless** > **Containers**. The containers page appears.
2. Click the relevant containers namespace.
3. Click the name of the container you want to manage.
4. In the **Network & Domains** tab, under **Private Network**, click **Detach Private Network**.
5. In the confirmation dialog, click **Detach Private Network**.

Your container is redeployed and is now detached from the PN.

## Delete a Private Network

<Message type="note">
  Before deleting a PN, you must [detach](/vpc/how-to/attach-resources-to-pn/#how-to-detach-a-resource-from-a-private-network) all resources attached to it.
</Message>

You can delete a PN from the VPC section of the console. See [Delete a Private Network](/vpc/how-to/delete-private-network/).
