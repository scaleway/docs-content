Managed Database for PostgreSQL and MySQL provides fully managed relational Database Instances, with MySQL or PostgreSQL as database engines.

Managed Database for PostgreSQL and MySQL lets you focus on development rather than administration or configuration. You do not need to set up the hardware or configure the software. Scaleway handles the provisioning and the configuration, and provides features such as high availability, data replication, automated backups, and user management.

<Requirements />

- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization

## Create a Database Instance

1. In the side menu, under **Databases**, click **PostgreSQL & MySQL**. The Managed Database for PostgreSQL and MySQL page opens.
2. Click **Create Database Instance**. The creation wizard opens.
3. Select the region in which you want to create your Database Instance.
4. Select a database engine, **PostgreSQL** or **MySQL**, then select a version from the dropdown.
5. Select a configuration. The following configurations are available:
    - **High Availability (1 primary node + 1 standby node)**: Creates a secondary node with an up-to-date replica of the Database Instance. If the primary node fails, the secondary node takes over requests.
    - **Standalone (1 node)**: Creates a Database Instance provisioned on a single node. You can upgrade it to High Availability after creation, but not the opposite.
6. (Optional) In the **Encryption at rest** section, check the box to encrypt the data of your Database Instance.
    <Message type="important">
      You cannot disable encryption at rest after you create the Database Instance. If you enable encryption at rest after creation, your Database Instance has a few seconds of downtime.
    </Message>
7. Choose a node type. In the **Usage** view, click **Show node types** under **Development** or **Production-ready**, then select a node type. You can also click **List** to see all node types.
8. Choose your storage type and capacity. The following storage types are available:
    - **Block Storage**: Your storage is separate from your compute resources, so you can increase it without changing your node type. Select **5K** or **15K** input/output operations per second (IOPS), then enter the storage capacity in GB, up to 10 TB.
    - **Local SSD Storage**: Your storage is fixed and tied to your compute resources. Local SSD Storage is only available with previous-generation node types (DB-DEV-X and DB-GP-X).
9. Choose a snapshot configuration. See [How to manage snapshots](/managed-databases-for-postgresql-and-mysql/how-to/manage-snapshots/) for more information.
    - **Automated**: Scaleway creates snapshots automatically once a day. This is the default option.
    - **Manual**: You create snapshots yourself. Manual snapshots are subject to quota limitations.
10. Create the credentials of the user.
11. Enter a **Database Instance name**.
12. (Optional) Add **Database Instance tags**.
13. Click **Create Database Instance** to confirm your choices and start the creation. The **Overview** tab of your Database Instance opens.

## Add users

1. In the side menu, under **Databases**, click **PostgreSQL & MySQL**. The list of your Database Instances appears.
2. From the region dropdown, select the geographical region of the Instance you want to manage.
3. Click the database name or <Icon name="more" /> > **More info**. The Database Instance information page opens.
4. Go to the **Users** tab. The list of users appears. If you have not created any users yet, the list contains the user you set up when you created your Database Instance.
5. Click **Create user**.
6. (Optional) Use the toggle to grant admin rights to the user. Admin rights let a user create logical databases and users. These rights do not override the permissions configured for the logical databases.
7. Enter a **username** and **password**.
8. (Optional) Go to the **Permissions** tab and select a permission type for each database. The following permission types are available:
    - **None:** No access to the database
    - **Read:** Allow users to read tables and fields in a database
    - **Read/Write:** Allow users to read/write content in databases
    - **All:** Allow users to create schemas and tables in addition to Read/Write rights
9. Click **Create user** to confirm. The user appears in the user list.

To update the password or permissions of a user, or to delete a user, click <Icon name="more" /> next to the user and select the corresponding option.

## Delete a Database Instance

1. In the side menu, under **Databases**, click **PostgreSQL & MySQL**. The list of your Database Instances appears.
2. From the region dropdown, select the geographical region of the Instance you want to manage.
3. Click the database name or <Icon name="more" /> > **More info**. The Database Instance information page opens.
4. Scroll down to the **Delete Database Instance** section.
    <Message type="important">
      Deleting a Database Instance is irreversible.
    </Message>
5. Click **Delete Database Instance**. A dialog box appears.
6. Type **DELETE** to confirm.
7. Click **Delete Database Instance**.

You can also delete your Instance from the list of your Database Instances. Click <Icon name="more" /> next to the Instance name, then click **Delete**.
