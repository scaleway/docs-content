This page shows you how to manage [secrets](/secret-manager/concepts/#secret) and their [versions](/secret-manager/concepts/#version) using the [Scaleway CLI](https://github.com/scaleway/scaleway-cli). The CLI allows you to script secret operations, for example in CI/CD pipelines or provisioning scripts, without using the Scaleway console.

<Requirements />

- A Scaleway account logged into the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/#owner) status or [IAM permissions](/iam/concepts/#permission) allowing you to perform actions in the intended Organization
- [Generated an API key](/iam/how-to/create-api-keys/) and enabled the `SecretManagerFullAccess` [permission set](/iam/reference-content/permission-sets/)
- [Installed and configured the Scaleway CLI](/scaleway-cli/quickstart/)

<Message type="note">
All commands on this page use the default `fr-par` [region](/secret-manager/concepts/#region). Add the `region=<region>` argument to any command to target another region.
</Message>

## Creating a secret

1. Run the following command to create a secret. Replace `my-secret` with the name of your secret.

    ```bash
    scw secret secret create name=my-secret description="Database password for my application"
    ```

    An output similar to the following displays:

    ```
    ID            11111111-1111-1111-1111-111111111111
    ProjectID     22222222-2222-2222-2222-222222222222
    Name          my-secret
    Status        ready
    CreatedAt     now
    UpdatedAt     now
    VersionCount  0
    Description   Database password for my application
    Managed       false
    Protected     false
    Type          opaque
    Path          /
    Region        fr-par
    Srn           srn://secret-manager.scw.eu/regions/fr-par/secrets/11111111-1111-1111-1111-111111111111
    ```

2. Copy the `ID` of your secret. You need it to manage your secret and its versions.

You can also specify the following optional arguments when you create a secret:

- `type`: the [secret type](/secret-manager/reference-content/secret-types-json-format/). Possible values are `opaque` (default), `certificate`, `key_value`, `basic_credentials`, `database_credentials`, and `ssh_key`.
- `path`: the [path](/secret-manager/concepts/#path) of the secret, used to organize your secrets in a folder-like structure (for example, `/production/database`).
- `tags.0=<tag>`: one or several [tags](/secret-manager/concepts/#tag) to help you filter your secrets. To add several tags, increment the index of each tag, for example `tags.0=my-app tags.1=production`.
- `protected=true`: enables [secret protection](/secret-manager/concepts/#secret-protection) to prevent the secret from being deleted.

For example, the following command creates a `key_value` secret stored under the `/production` path:

```bash
scw secret secret create name=my-app-config type=key_value path=/production tags.0=my-app
```

## Creating an ephemeral secret

An [ephemeral secret](/secret-manager/concepts/#ephemeral-secret) has a limited lifetime, defined by an [ephemeral policy](/secret-manager/concepts/#ephemeral-policy). All versions of the secret inherit the settings of the policy.

Run one of the following commands to create an ephemeral secret:

- To make each version expire after a given period, use the `ephemeral-policy.time-to-live` argument. The value must be between 1 second and 1 year, for example `30s`, `1h`, or `720h`.

    ```bash
    scw secret secret create name=my-temporary-secret ephemeral-policy.time-to-live=1h ephemeral-policy.action=delete
    ```

- To make each version expire after it is accessed once, use the `ephemeral-policy.expires-once-accessed=true` argument.

    ```bash
    scw secret secret create name=my-one-time-secret ephemeral-policy.expires-once-accessed=true ephemeral-policy.action=disable
    ```

The `ephemeral-policy.action` argument is required, and defines what happens to a version when it expires:

- `disable`: the version is [disabled](/secret-manager/concepts/#disabling-a-version). You can [enable it again](#enabling-and-disabling-a-version).
- `delete`: the version is deleted.

<Message type="important">
You can only apply an ephemeral policy when you create a secret. You can modify the policy of an ephemeral secret with the `scw secret secret update` command, but you cannot remove it.
</Message>

## Encrypting a secret with your own Key Manager key

By default, Secret Manager encrypts your secrets with keys that Scaleway manages. You can use your own [Key Manager](/key-manager/concepts/#key-management) key to encrypt a secret instead.

1. [Create a Key Manager key](/key-manager/how-to/create-km-key/) with the `aes_256_gcm` symmetric encryption algorithm, then [retrieve its ID](/key-manager/how-to/retrieve-km-key-id/).
2. Run the following command to create a secret encrypted with your key. Replace `<key-id>` with the ID of your key.

    ```bash
    scw secret secret create name=my-secret key-id=<key-id>
    ```

<Message type="important">
The CLI does not check the usage of the key when you create the secret. If the key is not a symmetric encryption key, the creation of the secret succeeds, but adding a version to it fails with a `key <key-id> is in an invalid state` error.
</Message>

## Adding a version to a secret

A secret does not contain any data until you add a version to it.

1. Run the following command to add a version to your secret. Replace `<secret-id>` with the ID of your secret.

    ```bash
    scw secret version create <secret-id> data='{"username":"admin","password":"my-super-secure-password"}'
    ```

    The `data` value must match the expected JSON format of the [secret type](/secret-manager/reference-content/secret-types-json-format/). For `opaque` secrets, you can use any value. If the value does not match the expected format, the CLI returns an `Invalid json` error.

    To [disable](/secret-manager/concepts/#disabling-a-version) the previous version when you create a new one, add the `disable-previous=true` argument:

    ```bash
    scw secret version create <secret-id> data='{"username":"admin","password":"my-new-password"}' disable-previous=true
    ```

<Message type="tip">
To avoid storing sensitive values in your shell history, load the content of your version from a file using the `@` prefix, for example `data=@./secret.json`.
</Message>

## Accessing a secret version

Run the following command to access the data of a version. Replace `<secret-id>` with the ID of your secret, and `1` with the revision number of the version.

```bash
scw secret version access <secret-id> revision=1
```

By default, the `Data` field of the output displays the content of the version encoded in base64. You can use `revision=latest` to access the most recent version, or `revision=latest_enabled` to access the most recent enabled version.

To use the value of your secret in a script, add the following arguments:

- `raw=true`: returns only the decoded content of the version, without metadata.
- `field=<field-name>`: returns only the value of the given JSON field.

For example, the following command stores the password of the latest enabled version in an environment variable:

```bash
export DB_PASSWORD=$(scw secret version access <secret-id> revision=latest_enabled field=password raw=true)
```

## Listing secrets and versions

- Run the following command to list the secrets of your Project:

    ```bash
    scw secret secret list
    ```

    You can filter the results using the `name`, `path`, `type`, and `tags.0` arguments. When you filter on several tags, the command only returns the secrets that have all the specified tags. For example:

    ```bash
    scw secret secret list path=/production
    ```

- Run the following command to list the versions of a secret:

    ```bash
    scw secret version list <secret-id>
    ```

## Enabling and disabling a version

- Run the following command to disable a version. Accessing a disabled version returns a `precondition failed` error.

    ```bash
    scw secret version disable <secret-id> revision=1
    ```

- Run the following command to enable a version again:

    ```bash
    scw secret version enable <secret-id> revision=1
    ```

## Updating a secret

Run the following command to update the metadata of a secret, such as its name, description, path, or tags:

```bash
scw secret secret update <secret-id> name=my-renamed-secret description="New description"
```

<Message type="note">
- Updating the tags of a secret replaces all its existing tags. To keep a tag, include it in the command.
- Updating a secret does not modify its content. To change the content of a secret, [add a new version](#adding-a-version-to-a-secret).
</Message>

## Using the JSON output in scripts

Add the `-o json` flag to any command to display its output in JSON format. You can then process the output with a tool such as [jq](https://jqlang.org/).

For example, the following commands create a secret, store its ID in a variable, and add a version to it:

```bash
SECRET_ID=$(scw secret secret create name=my-secret -o json | jq -r '.id')
scw secret version create "$SECRET_ID" data=@./secret.json
```

<Message type="note">
In the JSON output of the `scw secret version access` command, the `data` field contains the content of the version encoded in base64. Use the `raw=true` argument to retrieve the decoded content.
</Message>

## Deleting a version or a secret

- Run the following command to schedule the deletion of a version:

    ```bash
    scw secret version delete <secret-id> revision=1
    ```

- Run the following command to schedule the deletion of a secret and all its versions:

    ```bash
    scw secret secret delete <secret-id>
    ```

<Message type="important">
- You cannot delete a [protected secret](/secret-manager/concepts/#secret-protection). Run `scw secret secret unprotect <secret-id>` to disable secret protection first.
- The CLI displays a `successfully deleted` message, but secrets and versions enter a 7-day [scheduled deletion](/secret-manager/concepts/#scheduled-deletion) period, after which they are permanently deleted. Run `scw secret secret list scheduled-for-deletion=true` to list the secrets scheduled for deletion. You can [recover a secret](/secret-manager/how-to/recover-secrets/) or [recover a version](/secret-manager/how-to/recover-version/) from the Scaleway console before the end of this period.
</Message>
