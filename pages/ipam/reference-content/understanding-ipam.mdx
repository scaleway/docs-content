This page explains the scope, features, and behavior of Scaleway IP Address Manager (IPAM), including its support for public IP addresses.

## Overview

IP Address Manager (IPAM) is the Scaleway tool for planning, tracking, and managing the IP address space of Scaleway products. It acts as a single source of truth for the IP addresses of your Scaleway resources.

IPAM holds every IP address you reserve, along with the resource it is attached to, its scope, and its tags. Managed products such as Managed Databases and Load Balancers are fully integrated into IPAM, and the [DHCP server](/vpc/concepts/#dhcp) of Private Networks uses IPAM to assign private, static IP addresses to attached resources.

The key principle of IPAM is that an IP address has a lifecycle of its own, separate from the resource it serves. When you reserve an address, it belongs to your Organization until you release it. Detaching or deleting the resource does not release the address, so you keep it for the next resource you attach.

## Supported IP sources

An IPAM address belongs to one of the following **sources**: private IPs, public zonal IPs, public regional IPs. The source determines the scope of the address, the resources it can be attached to, and the filters available when you list it in the console.

| Source | Scope | Example | Used for |
| --- | --- | --- | --- |
| Private IPs | A single Private Network | `172.16.12.2/22` | Attaching resources to a Private Network, inside a VPC |
| Public zonal IPs | A single Availability Zone | `fr-par-1` | Exposing a zonal resource, such as an Instance, to the public internet |
| Public regional IPs | A whole region | `fr-par` | Exposing a resource to the public internet, with no attachment to a single Availability Zone |

### Private IPs

A private IP address comes from the [CIDR block](/vpc/concepts/#cidr-block) of one of your Private Networks. It identifies a resource on that network, and is not routed on the public internet. Resources attached to Private Networks in the same VPC reach each other over these addresses.

You can let the DHCP server of the Private Network auto-allocate an address when you attach a resource, or [reserve a specific address in advance](/ipam/how-to/reserve-ip/) and use it to attach the resource of your choice. Reserving an address stops it from being auto-allocated to any other resource joining the network.

Private IP addresses are shown in [CIDR notation](https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing#CIDR_notation). For example, `172.16.12.2/22` represents the address `172.16.12.2` and its associated block `172.16.12.0/22`.

### Public zonal IPs

A public zonal IP address is scoped to a single Availability Zone, such as `fr-par-1`. It is the address type used by resources that live in one Availability Zone, such as Instances, Elastic Metal servers, Load Balancers, and Public Gateways.

A zonal address can only be attached to a resource in the same Availability Zone. If you reserve an address in `fr-par-1`, you can move it between resources in `fr-par-1`, but not to a resource in `fr-par-2`.

### Public regional IPs

A public regional IP address is scoped to a whole region, such as `fr-par`, rather than to one Availability Zone within it. The address is not tied to a single Availability Zone, which makes it suitable for regional resources and for setups that need to survive the loss of an Availability Zone.
