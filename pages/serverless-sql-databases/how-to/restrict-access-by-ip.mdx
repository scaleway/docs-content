[IAM policies](/iam/policies-permissions/policy/) manage access to Serverless SQL Databases. You can add a [request-level condition](/iam/policies-permissions/understanding-request-level-conditions/), written in [Common Expression Language (CEL)](/iam/policies-permissions/understanding-policy-conditions/), to a policy rule so that the rule only applies to requests from specific IP addresses. Requests from any other IP address do not receive the permissions of the rule and cannot connect to the database. 

See [Create an IAM policy](/iam/policies-permissions/create-policy/) for more information about the policy creation process.

<Requirements />

- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
- A [Serverless SQL Database](/serverless-sql-databases/how-to/create-a-database/)
- The public IP addresses or IP ranges you want to allow

## Create a policy with an IP address condition

1. In the side menu, click **IAM**. The **Users** tab of the [Identity and Access Management dashboard](https://console.scaleway.com/iam/users) opens.
2. In the **Policies** tab, click **Create policy**. The creation wizard opens.
3. Enter a **name** and a description for the policy.
4. Select a **principal** for your policy. The [principal](/iam/concepts/glossary/#principal) is the user, application, or group whose credentials are used to connect to the database.
5. Select the **permission sets** for the rule in **Resource management**, such as **ServerlessSQLDatabaseReadWrite**. See [How to manage user permissions for Serverless SQL Databases](/serverless-sql-databases/how-to/manage-permissions/) for more information about each permission set.
6. Click **Next**.
7. Select a **scope** for the rule: **Specific projects** to grant the permissions on the Project that contains your database only, or **All projects** to grant them on all Projects.
8. Click **Next**.
9. Add a request-level condition to the rule that uses the `request.ip` variable, such as `request.ip == "82.96.173.45"`. See [CEL expression examples](#cel-expression-examples) for more examples, and [Request-level conditions](/iam/policies-permissions/understanding-request-level-conditions/) for more information.
10. Click **Confirm rule**. The rule appears in the list of rules of the policy.
11. Click **Create policy**. The overview page of the new policy opens.

The principal can now connect to the database only from the IP addresses defined in the condition.

## CEL expression examples

The `request.ip` variable contains the IP address the request comes from. Only public IP addresses are supported.

| Use case | CEL expression |
| :--- | :--- |
| Allow a single IP address | `request.ip == "82.96.173.45"` |
| Allow several IP addresses | `request.ip == "82.96.173.45" \|\| request.ip == "51.15.210.12"` |
| Allow an IP range | `cidr("82.96.173.0/24").containsIP(request.ip)` |
| Allow several IP ranges | `cidr("82.96.173.0/24").containsIP(request.ip) \|\| cidr("51.15.0.0/16").containsIP(request.ip)` |

See the [CEL conditions guide](/iam/policies-permissions/cel-conditions-guide/) for more information about the network functions you can use in conditions.

## Check the restriction

1. Connect to the database from an allowed IP address. The connection succeeds. See [How to connect to a Serverless SQL Database](/serverless-sql-databases/how-to/connect-to-a-database/) for more information.
2. Connect to the database from an IP address that is not in the condition, using the same credentials. The connection is refused.
