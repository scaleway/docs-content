Scaleway Generative APIs is a [model-as-a-service (MaaS)](https://www.scaleway.com/en/model-as-a-service/) offering for large language models and other AI models. You send a request to an HTTP endpoint, a model processes it, and you receive a response. You pay for what you use.

This page gives you the mental model for how the product fits together. If you just want to make your first call, see the [Quickstart](/generative-apis/quickstart/).

## How a request works

Every interaction with Scaleway Generative APIs follows the same flow:

<D2Schema title="Generative API calls" description="An application makes a call (HTTPS request) to Generative API endpoint, which routes to a model, then sends back the response to the application">
```d2

app: Your application {
  icon: scw:application
}

endpoint: Generative APIs endpoint {
  icon: scw:generative-api

model: "Model (Mistral, Llama, Pixtral, …)" {
  icon: scw:custom-model
}

response: "Response (text, tokens, embeddings, …)"

app -> endpoint: "HTTPS request (OpenAI-compatible)"
endpoint -> model: "Routes to a model"
model -> response: "Inference"
response -> app
```
</D2Schema>

You do not manage GPUs, containers, or model weights. You pick a model, send a prompt (or image, or audio), and get output. Scaleway manages the infrastructure for you.

## Key building blocks

Models
: The AI models available (language, vision, embedding, code, audio, etc.).

API
: The HTTP interface you call. OpenAI-compatible, so existing OpenAI SDKs work out of the box. 

Integrations
: Pre-built connectors for tools like Cursor, Claude Code, LangChain, n8n, and more.

Deployments
: Optional dedicated infrastructure for high-volume or custom-model workloads.

## Two ways to access a model

Scaleway Generative APIs offers 2 access modes: 
- **Serverless** – No setup. Pick a model, call the API, pay per token. This is the most accessible option, and the path that the [Quickstart](/generative-apis/quickstart/) follows.
- **Dedicated deployments** – You manage a dedicated instance for a model. You control scaling, networking, and access. You pay per instance-hour.

For most use cases, serverless is the right starting point. You move to a dedicated deployment when you need more control, a Private Network, a custom model, or predictable costs at high volume. 

## OpenAI compatibilty

The API follows the OpenAI Chat Completions schema. If you have used the OpenAI SDK, you can point it at the Scaleway endpoint and change your API key. 

This means: 
- `client.chat.completions.create(...)` works as-is
- Streaming, function calling, and structured outputs uses the same OpenAI parameters. 
- The [OpenAI compatibility](/generative-apis/api-cli/openai-compatibility/) page documents the exact mapping and any differences.

See the Generative APIs [API Documentation](https://www.scaleway.com/en/developers/api/generative-apis).

## Where it fits in Scaleway

Scaleway Generative APIs is managed through the same infrastructure as every other Scaleway product: 

Access control
: Scope with [Organizations and Projects](/organizations-and-projects/), and [IAM](/iam/). You can restrict which teams can call which models. 

Monitoring
: Metrics (tokens, latency, errors) and logs are available in [Cockpit](/cockpit/).

Billing
: Serveless: pay per token (input + output). Dedicated: pay per instance-hour.

Data handling
: Scaleway does not use your prompts and responses for training. See [Data privacy](/generative-apis/security/data-privacy/).
