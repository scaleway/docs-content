## Use environment variables

The following environment variables are injected by default in the workflow runs to improve and optimize data management.
For information on other tasks and concepts, see the [Data Orchestrator DSL Reference](/data-orchestrator/reference-content/dsl-reference/).


|      Variable name       |                  Description                   |              Sample value              |
| :----------------------- | :--------------------------------------------- | :------------------------------------- |
| `region`                 | Region of the workflow run                     | `fr-par`                               |
| `organizationId`         | ID of the Organization of the workflow         | `00000000-0000-0000-0000-000000000000` |
| `projectId`              | ID of the Project of the workflow              | `00000000-0000-0000-0000-000000000000` |
| `workflowDefinitionId`   | ID of the workflow definition                  | `00000000-0000-0000-0000-000000000000` |
| `workflowDefinitionName` | Name of the workflow definition                | `"dor-workflow-name"`                  |
| `workflowVersionId`      | ID of the workflow version                     | `00000000-0000-0000-0000-000000000000` |
| `workflowRunId`          | ID of the workflow run                         | `00000000-0000-0000-0000-000000000000` |
| `triggerType`            | Type of trigger that launched the workflow run | `manual` or `scheduled`                |

To reuse these environment variables, use the syntax `${ $workflow.<ENVIRONMENT_VARIABLE> }`. In the following examples, replace the placeholders with the appropriate values.

```yaml
do:
  - <TASK_NAME>:
      if: ${ $workflow.workflowDefinitionName == "<DOR_WORKFLOW_NAME>" }
      call: serverless_job
      with:
        id: "<SERVERLESS_JOB_ID>"
        region: "<REGION>"
```

When a workflow executes a Serverless Job, the environment variables are injected into the job with the following format:

- `SCW_WOFL_REGION`
- `SCW_WOFL_ORGANIZATION_ID`
- `SCW_WOFL_PROJECT_ID`
- `SCW_WOFL_DEFINITION_ID`
- `SCW_WOFL_DEFINITION_NAME`
- `SCW_WOFL_VERSION_ID`
- `SCW_WOFL_RUN_ID`
- `SCW_WOFL_TRIGGER_TYPE`
