You cannot move a running Instance directly to another Availability Zone (AZ). To move an Instance, you create snapshots of its volumes, export them to Object Storage, import them in the destination AZ, and create a new Instance from them. You can use the same process to move an Instance to another Project, which transfers the ownership of the Instance or its snapshots.

This process works for Instances that use Local Storage or Block Storage. You can perform it with the Scaleway console or the CLI.

<Requirements />
- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
- An [Instance](/instances/how-to/create-an-instance/)
- An [Object Storage bucket](/object-storage/how-to/create-a-bucket/) in the same region as the source and destination AZs
- The [Scaleway CLI](/scaleway-cli/quickstart/) installed, for CLI-based instructions
- A valid [API key](/iam/credentials/create-api-keys/) with sufficient permissions, for CLI-based instructions

Check the following points before you move your Instance:

- The destination AZ must support the Instance type you want to use. See the [Instances datasheet](/instances/reference-content/instances-datasheet/) for more information.
- Local Storage is tied to the hypervisor of the Instance. You cannot move Local Storage volumes directly to another AZ.
- You can detach Block Storage volumes and attach them to another Instance in the same AZ. To move them to another AZ, you must use snapshots.
- You cannot snapshot [scratch storage](/instances/reference-content/understanding-scratch-storage/). The new Instance does not contain the data stored on the scratch volumes of the original Instance.

## Move an Instance to another Availability Zone

### Create snapshots of the Instance volumes

<Message type="tip">
  You can create snapshots without stopping the Instance. To keep your data consistent, pause heavy write operations before you create the snapshots.
</Message>

1. In the Scaleway console side menu, go to **Compute** > **CPU & GPU Instances**. The [Instances dashboard](https://console.scaleway.com/instance/servers) opens.
2. Click the Instance you want to move. The **Overview** page of the Instance opens.
3. Click the **Storage** tab. The **Volumes** section lists the Local Storage and Block Storage volumes of the Instance.
4. Click **+ Create snapshot**. A dialog box appears.
5. Select the volume to snapshot.
6. Enter a name for the snapshot.
7. Select the snapshot type: **LSSD** for Local Storage or **BSSD** for Block Storage.
8. Click **Create snapshot**.
9. (Optional) Repeat steps 4 to 8 for each volume of the Instance to create a full backup.

### Export the snapshots to Object Storage

To move snapshots across AZs, you must export them to an Object Storage bucket in the same region as the source and destination AZs.

#### Export Local Storage snapshots with the console

1. In the Scaleway console side menu, go to **Storage** > **Local Storage**.
2. Click the **Snapshots** tab.
3. Click the snapshot you want to export.
4. Click **Actions** > **Copy to bucket**. A dialog box appears.
5. Enter a name for the QCOW2 file. The name must end with `.qcow` or `.qcow2`.
6. Select an Object Storage bucket in the same region.
7. Click **Copy snapshot to bucket**. The export starts. When the export is complete, the status of the snapshot turns green.

#### Export Block Storage snapshots with the CLI

The command depends on the API that manages your snapshot.

- To export a snapshot managed by the Block Storage API, run the following command:
    ```bash
    scw block snapshot export-to-object-storage zone=<ZONE> snapshot-id=<SNAPSHOT_ID> bucket=<BUCKET_NAME> key=<FILE_NAME>.qcow2
    ```

- To export a legacy Block Storage snapshot or a Local Storage snapshot managed by the Instances API, run the following command:
    ```bash
    scw instance snapshot export-to-object-storage zone=<ZONE> snapshot-id=<SNAPSHOT_ID> bucket=<BUCKET_NAME> key=<FILE_NAME>.qcow2
    ```

Replace the following placeholders in the commands:

- `<ZONE>`: the AZ of the snapshot (e.g., `fr-par-1`)
- `<SNAPSHOT_ID>`: the ID of the snapshot
- `<BUCKET_NAME>`: the name of your Object Storage bucket
- `<FILE_NAME>`: the name of the QCOW2 file to create

### Import the snapshots into the destination AZ

Import each QCOW2 object as a Local Storage or Block Storage snapshot in the destination AZ.

#### Import snapshots with the console

1. In the Scaleway console side menu, go to **Storage** > **Object Storage**.
2. Click the name of the bucket that contains your exported snapshot. The content of the bucket appears.
3. Click <Icon name="more" /> next to the name of the snapshot file.
4. Click **Import as snapshot**. A dialog box appears.
5. Enter a name for the snapshot, or keep the suggested name.
6. Select the destination AZ.
7. Select the snapshot type: Local Storage or Block Storage.
8. Click **Import object as snapshot**.

#### Import snapshots with the CLI

Run the following command to import a snapshot:

```bash
scw block snapshot import-from-object-storage name=<SNAPSHOT_NAME> bucket=<BUCKET_NAME> key=<FILE_NAME>.qcow2 size=<SIZE_IN_GB> project-id=<PROJECT_ID> zone=<ZONE>
```

Replace the following placeholders:

- `<SNAPSHOT_NAME>`: the name of the imported snapshot
- `<BUCKET_NAME>`: the name of your Object Storage bucket
- `<FILE_NAME>`: the name of the QCOW2 file
- `<SIZE_IN_GB>`: the size of the new snapshot, in GB
- `<PROJECT_ID>`: (optional) the ID of the Project to import the snapshot into
- `<ZONE>`: the destination AZ (e.g., `fr-par-2`)

### Create a new Instance in the destination AZ

#### Create an Instance with the console

1. In the Scaleway console side menu, go to **Compute** > **CPU & GPU Instances**. The [Instances dashboard](https://console.scaleway.com/instance/servers) opens.
2. Click **Create Instance** > **Create CPU Instance**. The Instance creation wizard opens.
3. Select the destination AZ.
4. Select the Instance type.
5. In the **Choose an image** step, click the **My snapshots** tab.
6. Select the imported snapshot.
7. Configure additional volumes, network settings, and flexible IP addresses according to your requirements. To keep the original public IP address, select it under **Select existing IPv4(s)**.
8. Click **Create Instance**. The new Instance appears in the list of your Instances.

#### Create an Instance with the CLI

Run the following command to create a new Instance with a Block Storage root volume from an imported snapshot:

```bash
scw instance server create image=none root-volume=block:<SNAPSHOT_ID> type=<COMMERCIAL_TYPE> zone=<ZONE> project-id=<PROJECT_ID>
```

Replace the following placeholders:

- `<SNAPSHOT_ID>`: the ID of the imported snapshot
- `<COMMERCIAL_TYPE>`: the commercial type of the new Instance (e.g., `POP2-4C-16G`)
- `<ZONE>`: the destination AZ
- `<PROJECT_ID>`: the ID of the destination Project

## Storage type considerations

### Local Storage

- The Instances API creates and manages Local Storage snapshots.
- You cannot detach a Local Storage volume from its Instance. Use snapshots to move its data to a new Instance.
- You can restore Local Storage (LSSD) snapshots only to Local Storage volumes.

### Block Storage

- You can restore Block Storage (BSSD) snapshots only to Block Storage volumes.
- To move a Block Storage volume to another Instance in the same AZ and Project, you can detach and reattach it without using snapshots:
    ```bash
    scw instance server detach-volume volume-id=<VOLUME_ID> zone=<ZONE>
    scw instance server attach-volume server-id=<INSTANCE_ID> volume-id=<VOLUME_ID> zone=<ZONE>
    ```

    Replace `<VOLUME_ID>` with the ID of the volume, `<INSTANCE_ID>` with the ID of the destination Instance, and `<ZONE>` with the AZ of the Instances.
