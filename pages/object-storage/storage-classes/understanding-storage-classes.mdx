Object Storage offers several storage classes to match the performance, access, resiliency, and cost requirements of your data. Each object has its own storage class, which you select at upload and can change later. Use colder classes for data you access less often to reduce your storage costs.

## Available storage classes

| Storage class | Amazon S3 name | Resiliency | Access | Recommended use |
|---|---|---|---|---|
| Standard Multi-AZ | `STANDARD` | Data distributed across 3 Availability Zones of a region | Immediate | Frequently accessed data, such as static assets, streaming, CDN origins, or work documents |
| Standard One Zone | `ONEZONE_IA` | Data distributed across 3 racks in a single Availability Zone | Immediate | Secondary backup copies and data you can easily recreate |
| Glacier | `GLACIER` | Data archived in the Paris DC4 underground data center | Restore required | Deep archiving of data you rarely access, such as legal documents or long-term backups |

Storage class availability varies by region. See [Product availability by region](https://www.scaleway.com/en/product-availability-by-region/?categories=storage) for the classes available in each region. See the [Object Storage pricing page](https://www.scaleway.com/en/pricing/storage/#object-storage) for the price of each class.

### Standard Multi-AZ

Standard Multi-AZ distributes your data across 3 [Availability Zones (AZ)](/object-storage/concepts/glossary/#region-and-availability-zone) of the same region, with 1 data center per AZ. If a complete data center fails, Object Storage rebuilds your data from the other AZs and keeps it accessible.

### Standard One Zone

Standard One Zone stores your data across 3 different racks in a single Availability Zone. This class costs less than Standard Multi-AZ, and suits data that you can recreate if the AZ becomes unavailable.

### Glacier

Glacier is a cold storage class designed for deep archiving. Objects in the Glacier class appear in your bucket, but you cannot download them directly: you must first [restore them](/object-storage/storage-classes/restore-from-glacier/) to the Standard Multi-AZ class. See [Understanding Glacier](/object-storage/storage-classes/understanding-glacier/).

## Choose and change a storage class

You can set the storage class of an object in the following ways:

- **At upload**: select the class in the console, or use the `--storage-class` option of the AWS CLI. You can upload objects directly to Glacier. See [How to upload objects](/object-storage/objects/upload-objects/).
- **For a single object**: edit its storage class in the console. Object Storage creates a copy of the object with the new class, which overwrites the previous object. See [How to manage storage classes](/object-storage/storage-classes/manage-storage-classes/).
- **For many objects or a whole bucket**: create a [lifecycle rule](/object-storage/storage-classes/lifecycle-rules/) that targets all objects, or objects that match a prefix or tags. Object Storage changes their class automatically after the delay you define.

## Allowed transitions

Transitions only go from warmer to colder classes:

- Standard Multi-AZ to Standard One Zone
- Standard Multi-AZ to Glacier
- Standard One Zone to Glacier

The same rules apply to lifecycle rules and to server-side copies. To move an object from Glacier back to a warmer class, [restore it](/object-storage/storage-classes/restore-from-glacier/). A restore always targets the Standard Multi-AZ class. You cannot use a lifecycle rule to restore objects from Glacier.

## When lifecycle transitions apply

Object Storage evaluates lifecycle rules every day at 00:00 UTC. The resulting action can take from 1 minute to 24 hours to complete. Rules that target a very large number of objects (several hundred thousand) can take longer.

For example, with a rule that transitions objects to Glacier 2 days after their creation:

1. You upload an object on April 6 at 14:00 UTC.
2. The rule triggers on April 8 at 23:59 UTC.
3. Object Storage transitions the object to Glacier no later than April 9 at 23:59 UTC.

See the [Lifecycle rules reference](/object-storage/storage-classes/lifecycle-rules-reference/) for the full list of transition and expiration elements.
