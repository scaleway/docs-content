Users can connect to a database and access its data. Each user has a different set of customizable permissions.

For advanced use cases, such as custom permissions or Structured Query Language (SQL) commands that the user permissions API does not support, see the [Advanced user permissions](/managed-databases-for-postgresql-and-mysql/api-cli/advanced-user-permissions/) documentation.

<Requirements />

- A Scaleway account logged in to the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/glossary/#owner) status or [IAM permissions](/iam/concepts/glossary/#permission) allowing you to perform actions in the intended Organization
- A [PostgreSQL or MySQL Database Instance](/managed-databases-for-postgresql-and-mysql/quickstart/)

## Create a user

1. In the side menu, under **Databases**, click **PostgreSQL & MySQL**. The list of your Database Instances appears.
2. From the region dropdown, select the geographical region of the Instance you want to manage.
3. Click the database name or <Icon name="more" /> > **More info**. The Database Instance information page opens.
4. Go to the **Users** tab. The list of users appears. If you have not created any users yet, the list contains the user you set up when you created your Database Instance.
5. Click **Create user**.
6. (Optional) Use the toggle to grant admin rights to the user. Admin rights let a user create logical databases and users. These rights do not override the permissions configured for the logical databases. You set logical database permissions in the **Permissions** tab.
7. Enter a **username** and **password**.
8. (Optional) Go to the **Permissions** tab and select a permission type for each database. The following permission types are available:
    - **None:** No access to the database
    - **Read:** Allow users to read tables and fields in a database
    - **Read/Write:** Allow users to read/write content in databases
    - **All:** Allow users to create schemas and tables in addition to Read/Write rights

    <Message type="important">
      Scaleway applies PostgreSQL permissions only to the items that exist when you set the configuration. Permissions do not apply to items created afterward.
      When you add database objects such as tables or sequences, your configured permissions automatically switch to **Custom**. The **Custom** setting ensures that your permissions remain valid for the items created before you reconfigured your database.
      You can use [PostgreSQL default privileges](https://www.postgresql.org/docs/current/sql-alterdefaultprivileges.html) to set default privileges for future objects.<br/>
      See the [Advanced user permissions](/managed-databases-for-postgresql-and-mysql/api-cli/advanced-user-permissions/) documentation for more information.
    </Message>
9. Click **Create user** to confirm. The user appears in the user list.

To update the password or permissions of a user, or to delete a user, click <Icon name="more" /> next to the user and select the corresponding option.

## Set permissions for an existing user

Permissions define the actions a user can perform on a logical database. When you create your Database Instance, Scaleway automatically generates a database user and grants it permissions. Users you create afterward have no permissions by default.

1. In the side menu, under **Databases**, click **PostgreSQL & MySQL**. The list of your Database Instances appears.
2. From the region dropdown, select the geographical region of the Instance you want to manage.
3. Click the database name or <Icon name="more" /> > **More info**. The Database Instance information page opens.
4. Go to the **Users** tab. The list of users appears.
5. Click <Icon name="more" /> > **Update permissions** next to the user. The user permissions panel opens.
6. Select a permission type for each database. The following permission types are available:
    - **None:** No access to the database
    - **Read:** Allow users to read tables and fields in a database
    - **Read/Write:** Allow users to read/write content in databases
    - **All:** Allow users to create schemas and tables in addition to Read/Write rights
7. Click **Update user** to confirm.

## Permissions for many databases and users

If your Database Instance has a large number of databases and users, the Scaleway console may have difficulty applying permission changes. For these use cases, use the [Scaleway API](https://www.scaleway.com/en/developers/api/managed-databases-for-postgresql-and-mysql/), the [Scaleway CLI](https://github.com/scaleway/scaleway-cli), or [Terraform](https://registry.terraform.io/providers/scaleway/scaleway/latest/docs) instead.
