This page explains how to reuse components in Data Orchestrator workflow definitions.
For information on other tasks and concepts, see the [Data Orchestrator DSL Reference](/data-orchestrator/reference-content/dsl-reference/).

In the following examples, replace the placeholders with the appropriate values.

## Use environment variables

The following environment variables are available in the workflow definition:

- `region`
- `organizationId`
- `projectId`
- `workflowDefinitionId`
- `workflowDefinitionName`
- `workflowVersionId`
- `workflowRunId`
- `triggerType` (manual or scheduled)

To reuse these environment variables, use the syntax `${ .workflow.<ENVIRONMENT_VARIABLE> }`. For example: 

```yaml
  - task1:
    if: ${ $workflow.workflowDefinitionName == "<WORKFLOW_NAME_001>" }
    call: serverless_job
    with:
      id: "<SERVERLESS_JOB_ID>"
      region: "<REGION>"
```

When a workflow executes a Serverless Job, the environment variables are injected into the job with the following format:

- `SCW_WOFL_REGION`
- `SCW_WOFL_ORGANIZATION_ID`
- `SCW_WOFL_PROJECT_ID`
- `SCW_WOFL_DEFINITION_ID`
- `SCW_WOFL_DEFINITION_NAME`
- `SCW_WOFL_VERSION_ID`
- `SCW_WOFL_RUN_ID`
- `SCW_WOFL_TRIGGER_TYPE`

<Message type="tip">
  To make it shorter, set a variable in your workflow definition using [set](/data-orchestrator/reference-content/dsl-reference#set).
</Message>
