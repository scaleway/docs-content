This page includes the specificities of the environmental footprint calculation for Serverless Compute products (Serverless Functions, Serverless Containers, and Serverless Jobs).

## Calculation aspects

Unlike traditional cloud computing where a user provisions a full instance, Serverless Compute products rely on a shared, dynamically allocated pool of underlying instances. Therefore, the environmental footprint of a Serverless Compute workload is calculated as a ratio. User impact represents a fraction of the total reserved hardware pool's impact, strictly proportional to the vCPU and RAM a function, container, or job consumes during execution.

## Allocation methodology

The base environmental impact for any Serverless resource is allocated by weighing the specific CPU and RAM consumption of the user against the total capacity and impact of the shared instance pool. 

The allocation follows this formula: Total Impact = (Pool CPU Impact Ratio × User vCPU Share) + (Pool RAM Impact Ratio × User RAM Share)

While the base formula applies to the entire Serverless ecosystem, the resource measurement adapts to each specific product:
- *Serverless Functions*: Functions execute lightweight code triggered by events. The consumed RAM is derived from the billed memory consumption (GB-s) and the exact execution time (ms). The vCPU allocation is always strictly proportional to the RAM used (calculated as a fixed ratio of 0.5468 * RAM).
   - Provisioned Concurrency: If a user pre-provisions instances, the manufacturing impact of those reserved resources is fully allocated to them. To prevent double-counting, any active consumption that uses this provisioned capacity overrides the base provisioned impact for that specific portion.

- *Serverless Containers*: Containers allow the deployment of complete Docker images and web frameworks. They share the exact same hardware pool and allocation formula as Serverless Functions, but the consumed vCPU and RAM are measured and allocated directly without intermediate proportional calculations.   

- *Serverless Jobs*: Jobs are designed for heavy, asynchronous background tasks. They use the same direct measurement and allocation formula as Containers, but they are executed on a separate, dedicated hardware pool specifically optimized for background workloads.

- *Control Plane:* The shared management infrastructure (Control Plane) required to orchestrate all 3 Serverless products is aggregated and its impact is distributed across the footprint of the services. 

## Usage impact

Usage impact reflects the actual energy consumed during the execution phase. For Serverless workloads, resources are consumed primarily when the code or container is actively running (e.g., waking up in milliseconds to process an HTTP request or event, and then scaling back down). Note that resources consumed through the "Free Tier" generate the exact same environmental impact as paid consumption. Therefore, "Free Tier" usage is tracked and calculated identically to standard usage to ensure the carbon footprint is comprehensively and transparently measured.
