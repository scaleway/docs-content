Scratch storage is fast, temporary local Non-Volatile Memory Express (NVMe) storage that you can attach to some Instances. Scratch volumes are located on the physical hypervisor that hosts your Instance, which gives them very low latency compared to network-based storage.

Scratch storage is designed for data you can afford to lose. It is not persistent: several common actions on your Instance, such as powering it off or changing its offer type, permanently erase all data stored on its scratch volumes.

## Compatible Instances

Scratch storage is available on the following Instance offers:

- [Standard3-x](/instances/reference-content/instances-datasheet/#standard3-x-instances) (General Purpose)
- [Compute3-x](/instances/reference-content/instances-datasheet/#compute3-x-instances) (Specialized)
- [Memory3-x](/instances/reference-content/instances-datasheet/#memory3-x-instances) (Specialized)

The maximum size of scratch storage depends on the Instance offer. The console shows the maximum size available when you add a scratch volume.

<Message type="note">
  H100, H100-SXM, L40S, and B300-SXM GPU Instances come with their own scratch storage, which Scaleway creates automatically. See the [Use scratch storage on GPU Instances](/gpu/how-to/use-scratch-storage-h100-instances/) documentation for more information.
</Message>

## Use cases

Scratch storage suits workloads that need fast disk access for short-lived or reproducible data, such as:

- Caches, such as build caches or package caches
- Temporary files and intermediate results of data processing jobs
- Swap space or temporary database files
- Data that your application can rebuild or download again, such as the local state of a Kubernetes node or a replica of a distributed database

Do not use scratch storage for:

- The operating system of your Instance (you cannot boot from a scratch volume)
- Application data, databases, or files that are not replicated elsewhere
- Data that must survive a power-off, a resize, or a hardware failure

## Actions that erase scratch storage data

The following table shows which actions keep or erase the data stored on scratch volumes.

| Action | Scratch storage data |
|--------|----------------------|
| Rebooting the Instance from the console, API, or CLI | Kept |
| Rebooting the OS from inside the Instance (`reboot`) | Kept |
| Switching the Instance to [standby mode](/instances/how-to/use-standby-mode/) | Kept |
| Shutting down the OS from inside the Instance (`poweroff`), which switches the Instance to standby mode | Kept |
| [Powering off](/instances/how-to/power-off-instance/) the Instance from the console, API, or CLI | Erased |
| [Changing the offer type](/instances/how-to/resize-instances/) of the Instance (resizing) | Erased |
| [Migrating the Instance](/instances/how-to/migrate-instances/) using an image or a snapshot | Erased, because images and snapshots do not include scratch volumes |
| Deleting the scratch volume | Erased |
| [Deleting the Instance](/instances/how-to/delete-instance/) | Erased, because scratch volumes are deleted with the Instance |
| Hardware failure of the hypervisor | Erased |

When you power on an Instance after a power-off, its scratch volumes are empty and unformatted. You must create a file system on them again before you use them. See the [Use scratch storage](/instances/how-to/use-scratch-storage/#create-a-file-system-on-a-scratch-volume) documentation for more information.

## Characteristics and limitations

| | Scratch storage | Block Storage |
|---|---|---|
| Location | Local NVMe disk on the hypervisor | Network-attached |
| Persistence | Not persistent | Persistent |
| Snapshots and images | Not supported | Supported |
| Bootable | No | Yes |
| Resize after creation | No | Yes (increase only) |
| Detach and attach to another Instance | No | Yes |
| Encryption settings | Not configurable | Optional, at creation |

Scratch volumes are attached to the Instance as raw block devices. They have no partition table and no file system when Scaleway creates them.

## Pricing

Scratch storage on Standard3-x, Compute3-x, and Memory3-x Instances is billed according to its size, in addition to the price of the Instance. The console shows the monthly price of the volume when you select the volume type. See the [Scaleway storage pricing page](https://www.scaleway.com/en/pricing/storage/) for more information.
