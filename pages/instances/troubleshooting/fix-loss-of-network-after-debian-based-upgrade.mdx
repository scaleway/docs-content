When upgrading a debian based O/S image to the latest version, you may experience a loss of network connectivity if your instance is connected to a private network.

Typically, this may happen when Ubuntu is upgraded from either Ubuntu 22.04 Jammy Jellyfish or Ubuntu 24.04 Noble Numbat to Ubuntu 26.04 Resolute Raccoon.

This is caused by a change of behavior of netplan which is no longer able to read the file generated by `/usr/bin/scw-vpc-ifup`.

<Message type="note">
  This guide only applies to instances that have had their O/S upgraded from a previous version. New instances do not encounter this situation.
</Message>

## You are about to upgrade our instance's O/S to the latest version

Before upgrading the O/S make sure that the `scaleway-ecosystem` package is at least at version **0.0.17-1** or later to avoid this situation.

If you have not been able to update the `scaleway-ecosystem` package prior to upgrading the O/S, you may find yourself unable to connect to the instance. To remediate this situation apply the following steps.

## Your Instance has lost network connectivity

[Rescue mode](/instances/concepts/#rescue-mode) allows you to boot your Instance into a temporary operating system, running from the Instance's RAM. Rescue mode is often used to diagnose and resolve issues such as faulty kernel configurations, networking issues, firewall configurations, and more.

1. Switch the Instance's `boot-type` to `rescue` and reboot your Instance into rescue mode using the [CLI](/scaleway-cli/quickstart/):
   ```
   scw instance server stop <Instance_ID>
   # Wait for the instance to be stopped.
   scw instance server update <Instance_ID> boot-type=rescue
   scw instance server start <Instance_ID>
   ```
   <Message type="note">
       Replace `<Instance_ID>` with the unique ID of your Instance, e.g. `0500ebd2-d70d-49af-a969-3ac09b6f7fff`.
   </Message>

2. Once the Instance is rebooted, log into your Instance using [SSH](/instances/how-to/connect-to-instance/) and set up the environment to be able to chroot into it:
   ```bash
   cat /proc/partitions
   major minor #blocks name

   7        0      65480 loop0
   7        1      89120 loop1
   7        2      39760 loop2
   252      0   19531250 vda
   252      1   19417569 vda1
   252     14       4096 vda14
   252     15     108544 vda15
   8        0    9765625 sda
   8        1    3240943 sda1
   8       14       4096 sda14
   8       15     108544 sda15

   ```
   Then mount the partitions and get into the `chroot`:

   ```bash
   mount /dev/vda1 /mnt
   chroot /mnt
   ```
3. Modify the file **/usr/bin/scw-vpc-ifup.netplan** file to apply the fix.
   The modification consists in adding the `umask 022` command after the `EoF` marker. After the modification, the file should looks like this

   ```
   #!/bin/bash

   iface=$(basename ${1})

   mkdir -p /run/netplan

   umask 077
   rm -f /etc/netplan/60-$iface-vpc.yaml
   cat > /run/netplan/60-$iface-vpc.yaml << EoF
   network:
     version: 2
     ethernets:
       $iface:
         dhcp4: true
         dhcp4-overrides:
           route-metric: 50
   EoF
   umask 022
   netplan apply
   ```

4. Get out of the `chroot` and remove the mounts:
   ```bash
   umount /mnt
   ```
5. Stop the Instance, switch back the Instance's `boot_type` to `local`, and reboot the Instance:
   ```
   scw instance server stop <Instance_ID>
   # Wait for the instance to be stopped
   scw instance server update <Instance_ID> boot-type=local
   scw instance server start <Instance_ID>
   ```
   Once rebooted, your Instance will be reachable again.

6. Install the definitive correction

   The modified file is part of the `scaleway-ecosystem` package. A new package has been release with the correction so the newest package should be installed to ensure that a definitive fix is in place
   ```bash
   apt get update
   apt -y install scaleway-ecosystem
   ```
