Data Orchestrator can use secrets stored in Scaleway [Secret Manager](https://www.scaleway.com/en/secret-manager/).
To reuse secrets in your workflow definition, use `secrets` to reference them.

In the following examples, replace the placeholders with the appropriate values.

<Tabs>
  <TabsTab label="Basic authentication">

    The following example shows how to reference and use a secret for a basic authentication in a workflow definition:

    ```yaml
    use:
      secrets:
        - <BASIC_SECRET_NAME>
      authentications:
        <AUTHENTICATION_VARIABLE_NAME>:
          basic:
            use: <BASIC_SECRET_NAME>
    do:
      - <TASK_NAME>:
          call: http
          with:
            method: GET
            endpoint:
              uri: <URI_EXAMPLE>
              authentication:
                use: <AUTHENTICATION_VARIABLE_NAME>
    ```

    The values of the secret must match the expected format for the authentication type. For basic authentication, the secret must contain a `username` and a `password`. For more information, see [Authentication](/data-orchestrator/reference-content/dsl-reference#authentication).

  </TabsTab>

  <TabsTab label="Bearer authentication">
    The following example shows how to reference and use a secret for a bearer authentication in a workflow definition:

    ```yaml
    use:
      secrets:
        - <BEARER_SECRET_NAME>
      authentications:
        <AUTHENTICATION_VARIABLE_NAME>:
          bearer:
            use: <BEARER_SECRET_NAME>
    do:
      - <TASK_NAME>:

            method: GET
            endpoint:
              uri: <URI_EXAMPLE>
              authentication:
                use: <AUTHENTICATION_VARIABLE_NAME>
    ```

    The values of the secret must match the expected format for the authentication type. For bearer authentication, the secret must contain a `token`. For more information, see [Authentication](/data-orchestrator/reference-content/dsl-reference#authentication).

  </TabsTab>

  </TabsTab>
</Tabs>

<Message type="tip">
  You can also use secrets directly in a jq expression, for example with `${ $secrets.'<BASIC_SECRET_NAME>'.password }`.
</Message>
