This tutorial provides a step-by-step guide for deploying n8n, an open-source workflow automation platform, on the Scaleway cloud platform. It covers the entire process, from setting up the required infrastructure including Serverless Containers, Managed Database, and Object Storage, to configuring and running n8n for workflow automation.

<Requirements />

- A Scaleway account logged into the [console](https://console.scaleway.com)
- [Owner](/iam/concepts/#owner) status or [IAM permissions](/iam/concepts/#permission) allowing you to perform actions in the intended Organization

## Prerequisites

n8n requires the following Scaleway services for a production-ready deployment:

- **Serverless Containers** to run the n8n container image
- **Managed Database** to store workflows and execution history
- **Object Storage** to store binary data

<Message type="note">
Serverless Containers are stateless, meaning container disk space is temporary. This tutorial configures persistent storage using Managed Database and Object Storage to ensure your workflows and data persist across container restarts.
</Message>

## Create a PostgreSQL Managed Database

n8n requires a database for persistent storage of workflows, executions, and configuration data.

1. Click **PostgreSQL and MySQL** under **Databases** on the side menu. If you do not have a database already created, the creation page displays.
2. Select the geographical region of the Instance you want to manage from the drop-down.
3. Click **Create Database Instance**. The creation wizard displays.

2. Click **Create Database** and select **PostgreSQL**.

3. Configure the database instance:
   - Select a plan suitable for your needs (DB-PLAY2-PICO is sufficient for testing)
   - Choose your preferred region
   - Click **Create**

4. Once the database is provisioned, create a database named `n8n` and a dedicated user with a secure password.

5. Attach the database to a Private Network:
   - In the database configuration, navigate to the **Network** tab
   - Click **Add Private Network**
   - Select an existing Private Network or create a new one
   - Click **Add**

<Message type="important">
Store the database host, username, and password securely. You will need these credentials to configure n8n environment variables.
</Message>

## Step 2: Create an Object Storage bucket

Since Serverless Containers have temporary disk space, configure Object Storage to store binary data such as uploaded files and execution artifacts.

1. Navigate to **Object Storage** in the Scaleway Console.

2. Click **Create a bucket** and enter a name (for example, `n8n-data-[your-name]`).

3. Select your preferred region and click **Create**.

4. Generate API credentials:
   - Navigate to **IAM** in the Scaleway Console
   - Click **Create API Key**
   - Give the API key a descriptive name
   - Copy the **Access Key** and **Secret Key** and store them securely

5. Note your bucket's endpoint URL (for example, `s3.fr-par.scw.cloud`).

## Step 3: Deploy n8n on Serverless Containers

You can deploy n8n using either the Scaleway Console or the `scw` CLI. This tutorial uses the Console.

### Create a namespace

1. Navigate to **Serverless Containers** in the Scaleway Console.

2. Click **Create a namespace** and enter a name (for example, `automation-tools`).

3. Select your preferred region and click **Create**.

### Create the container

1. In your newly created namespace, click **Deploy a container**.

2. Configure the container settings:
   - **Image**: `docker.io/n8nio/n8n:latest`
   - **Port**: `5678`
   - **CPU**: At least 0.5 vCPU
   - **Memory**: At least 1024 MB (n8n requires more resources than a simple API)
   - **Minimum instances**: 1 (to avoid cold starts)

3. Configure environment variables. Click the **Environment variables** tab and add the following variables:

   | Variable | Value |
   | -------- | ----- |
   | `DB_TYPE` | `postgresdb` |
   | `DB_POSTGRESDB_HOST` | Your database host IP |
   | `DB_POSTGRESDB_PORT` | `5432` |
   | `DB_POSTGRESDB_DATABASE` | `n8n` |
   | `DB_POSTGRESDB_USER` | Your database username |
   | `N8N_BINARY_DATA_STORAGE_MODE` | `s3` |
   | `N8N_EXTERNAL_STORAGE_S3_BUCKET_NAME` | Your bucket name |
   | `N8N_EXTERNAL_STORAGE_S3_BUCKET_REGION` | Your region (for example, `fr-par`) |
   | `N8N_EXTERNAL_STORAGE_S3_HOST` | Your bucket endpoint (for example, `s3.fr-par.scw.cloud`) |
   | `N8N_EXTERNAL_STORAGE_S3_ACCESS_KEY` | Your Object Storage access key |

4. Configure secrets. Click the **Secrets** tab and add the following secrets:

   | Secret | Value |
   | ------ | ----- |
   | `DB_PASSWORD` | Your PostgreSQL password |
   | `N8N_ENCRYPTION_KEY` | A random 32+ character string |
   | `N8N_EXTERNAL_STORAGE_S3_ACCESS_SECRET` | Your Object Storage secret key |

<Message type="important">
Store sensitive values like database passwords, encryption keys, and API secrets as **secrets** rather than plain environment variables. Secrets are encrypted and never exposed in logs.
</Message>

5. Click **Deploy** to create the container.

<Message type="tip">
For advanced configuration options and additional environment variables, refer to the [n8n official documentation](https://docs.n8n.io/hosting/configuration/environment-variables/).
</Message>

## Accessing n8n

Once the container is deployed and running:

1. Navigate to the **Endpoints** tab of your container.

2. Copy the endpoint URL and open it in your web browser.

3. You will be prompted to create an admin account for n8n on first access.

## Next steps

After successfully deploying n8n, you can:

- Create your first workflow using the n8n editor
- Explore the [n8n template library](https://n8n.io/workflows) for pre-built automations
- Configure webhooks to trigger workflows from external services
- Set up credentials for secure API integrations
- Monitor execution history and logs in the n8n dashboard
