Scaleway Serverless Containers automatically inject several HTTP headers into every incoming request. These headers provide metadata about the request, the client, and the routing path through the Scaleway infrastructure.

You can use these headers within your container logic for logging, security, and request tracing.

## Injected headers reference

The following headers are available in the request object of your container.

| Header | Description |
| :--- | :--- |
| `X-Forwarded-For` | A standard header used to identify the originating IP address of a client connecting through an HTTP proxy or load balancer. |
| `X-Forwarded-Proto` | A header indicating the protocol (HTTP or HTTPS) used by the client to connect to the container. |
| `X-Real-IP` | A header containing the IP of the container caller. Scaleway overwrites this header even if it has been explicitly passed. |
| `X-Request-ID` | A unique string assigned to each incoming request to facilitate tracing and debugging. |

<Message type="note">
  If there is one or more proxies between the client and the container, the `X-Real-IP` header contains the IP address of the last proxy, not the client. To retrieve the client IP address, use the `X-Forwarded-For` header instead. Clients can modify the `X-Forwarded-For` value, so do not rely on it for security purposes.
</Message>

Alongside these headers, the following headers are set for internal purposes. Users should be careful when using them, as their presence/contents is not guaranteed:

| Header | Description |
| :--- | :--- |
| `K-Proxy-Request` | **Internal.** Used by the underlying architecture. |
| `X-SCW-Source` | **Internal.** Used to determine if the request comes from a container private endpoint. |
| `X-Envoy-External-Address` | **Deprecated.** Prefer using `X-Real-IP`. |

## Detailed use cases

### Request tracing and debugging

The `X-Request-ID` header is essential for distributed tracing. Each request receives a unique identifier that persists throughout the lifecycle of the request within the Scaleway ecosystem.

* **Log correlation**: Log the `X-Request-ID` at the start of your container. If a request fails, you can use this ID to search your [Serverless Containers logs](/serverless-containers/monitoring/monitor-container/) for entries related to that specific execution. The request ID does not appear in user logs by default. To include it, propagate the header value yourself.
* **Cross-service tracking**: If your container calls another service, pass the `X-Request-ID` along to maintain a consistent trace across your architecture.

### Client IP identification

Use the `X-Real-IP` header to identify the IP address of the client. It lists the IP addresses the request passed through, with the original client IP address first. Clients can modify the `X-Forwarded-For` value, so do not rely on it for security purposes.

* **Security and filtering**: Use `X-Real-IP` to implement IP-based rate limiting, or to allow or deny requests from specific geographic regions within your application logic.
* **Analytics**: Use `X-Real-IP` to determine the general location of your users without relying on internal routing IPs.

### Protocol enforcement

The `X-Forwarded-Proto` header allows your container to determine if the user is connecting over a secure connection.

* **HTTPS redirection**: If your container logic requires a secure connection, you can check if `X-Forwarded-Proto` is `http` and respond with a redirect to the HTTPS version of your endpoint.

<Message type="note">
Because Scaleway Serverless Containers are served via HTTPS by default, this header usually reflects `https` for external requests.
</Message>

### Container private endpoint detection

The `X-SCW-Source` header is used internally to determine if the request originates from a container private endpoint. See [Use Serverless Containers with Private Networks](/serverless-containers/networking/use-private-networks/) for more information.
