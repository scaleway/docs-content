## Create a Data Orchestrator workflow

1. In the [Scaleway console](https://console.scaleway.com) side menu, go to **Data & Analytics** > **Data Orchestrator**. The list of your workflows appears.
2. Click **Create workflow**. The Data Orchestrator workflow creation wizard opens.
3. Select the region for your workflow.
4. Enter a name or use the automatically generated one.
5. (Optional) Enter a description.
6. Click **Create workflow only** to finish, or click **Create workflow and add tasks** to add tasks or upload a workflow definition file next.

### Create workflow tasks using the Scaleway console

<Message type="note">
  In the current Beta, the Scaleway console only supports the creation of Serverless Job tasks and simple connectors. Other tasks must be created using a workflow definition file.
</Message>

After creating a workflow, you can use the Scaleway console to create tasks manually or upload a workflow definition file.
If you want to create a workflow using a workflow definition file, see [Create a workflow definition YAML file](#create-a-workflow-definition-yaml-file).

This section explains how to create a sequential workflow with 3 Serverless Jobs using the Scaleway console in **Graph view**.

1. Click **Create workflow and add tasks** at the end of the workflow creation, or click **Edit** in the Overview tab of an existing workflow.
2. Click **Choose a job** to create the first task. The graph view opens with an empty job task created.
3. Click the empty job task, then:
    1. Select the region of the job.
    2. Select the job you want to use. 
    
    If the job does not exist yet, click **Create job** to open the Serverless Jobs creation wizard in a new tab. Once you have created the job, click **Refresh list** to display it. 
4. In the tasks menu on the left, click **Serverless Jobs** to create a new empty job task. The new empty job task appears to the right of the previous task.
6. Repeat the previous step to create a third Serverless Job.
6. Data Orchestrator workflows are executed from left to right, use drag and drop to order your tasks accordingly.
8. Drag the connector on the right side of the first task to the connector on the left side of the second task to link them.
9. Repeat the previous step to link the second and third tasks.
10. Click **Save changes** to finish, or click **Save and run** to save the workflow and run it immediately.

### Create a workflow definition YAML file

You can upload a YAML file to use more complex workflows in Data Orchestrator.

<Message type="tip">
  This is a basic example of a sequential workflow using 3 Serverless Jobs. For more examples, see the [Action tasks](/data-orchestrator/reference-content/action-tasks/) and [Logic tasks](/data-orchestrator/reference-content/logic-tasks/) documentation.
  See [Workflow schema](/data-orchestrator/reference-content/workflow-schema/) to download the Data Orchestrator workflow schema to help you create your workflow definition file.
</Message>

1. Create a YAML file, copy and paste the following content into the file.
    ```yaml
    document:
      dsl: 1.0.3
      namespace: <NAMESPACE_NAME>
      name: <WORKFLOW_NAME>
      version: 1.0.0
    do:
    - task1:
        call: "serverless_job"
        metadata:
          description: "The first job"
        with:
          id: "<SERVERLESS_JOB1_ID>"
          region: "fr-par"
    - task2:
        call: "serverless_job"
        metadata:
          description: "The second job"
        with:
          id: "<SERVERLESS_JOB2_ID>"
          region: "fr-par"
    - task3:
        call: "serverless_job"
        metadata:
          description: "The third job"
        with:
          id: "<SERVERLESS_JOB3_ID>"
          region: "fr-par"
    ```
2. Replace the ID placeholders with the IDs of your Serverless Jobs. You can copy them from the [Serverless Jobs page](https://console.scaleway.com/serverless-jobs/) of the console.
    <Message type="note">
      The fields `namespace` and `name` are required. They can be used as metadata to help organize your YAML files. For more details, see the [Workflow definition properties](#workflow-definition-properties) table.
    </Message>
3. Save the YAML file.

#### Workflow definition properties

| Property&nbsp;name |         Type         | Required |                         Description                          |
| :----------------- | :------------------: | :------: | :----------------------------------------------------------- |
| `dsl`              |        string        |   yes    | The version of the DSL used to define the workflow.          |
| `namespace`        |        string        |   yes    | The namespace of the workflow.                               |
| `name`             |        string        |   yes    | The name of the workflow.                                   |
| `version`          |        string        |   yes    | The [semantic version](https://semver.org/) of the workflow. |
| `title`            |        string        |    no    | The title of the workflow.                                  |
| `summary`          |        string        |    no    | The Markdown summary of the workflow.                       |
| `tags`             | map [string, string] |    no    | A key/value mapping of the tags of the workflow, if any.    |
| `metadata`         |         map          |    no    | Additional information about the workflow.                   |
